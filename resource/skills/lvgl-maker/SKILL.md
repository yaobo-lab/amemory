# LVGL 界面设计稿还原

根据设计图实现可编译、可交互、可释放的 LVGL 页面。设计图决定视觉效果，参考模板决定页面骨架和同类业务流程，仓库现有公共组件与架构约束决定最终实现方式。不要只画静态界面，也不要机械复制模板中的设备属性、资源名或历史问题。

## 同时遵守的项目规范

本技能涉及 `src/app` 的一方 C/LVGL 代码。开始实现前读取并遵守 `../embedded-layer-architecture/SKILL.md`，再按其要求读取相关 references。若本技能与项目通用规范冲突，以项目通用规范和用户当前明确要求为准。

## 用户输入格式

优先接受以下格式：

```text
设计图：随消息附图多张
存放路径：src/app/device/fan_infrared
参考模板：src/app/device/light_dimming.c
功能说明：红外风扇详情页，支持开关、风速和摇头（可选）
SPK：ir.fan
交互/协议：on_off、speed、oscillation（可选）
默认属性：on_off=on、speed=4（可选）
测试数据：设备名、演示 device_id、楼层/房间、是否收藏（可选）
资源说明：图标或资源目录（可选）
```

输入解释：

- `设计图`、`存放路径`、`参考模板` 是核心输入。
- 将无扩展名的 `存放路径` 解释为目标模块前缀。例如 `src/app/device/fan_infrared` 对应创建 `fan_infrared.c` 和 `fan_infrared.h`。
- 如果 `存放路径` 以 `.c` 或 `.h` 结尾，去掉扩展名后创建配对文件。
- 如果路径仅指向目录，且无法从上下文确定模块名，先询问模块名，不要自行命名。
- `参考模板` 可以是 `.c`、`.h` 或无扩展名模块路径；至少读取其 `.c` 和 `.h` 配对文件。
- 新增设备时，`SPK`、属性 key、类型、枚举/范围和控制语义是核心输入；优先从协议表、用户说明和现有同类设备核实。
- 用户没有指定测试记录但要求新增完整设备时，默认创建带 `gui-demo-` 前缀的明确演示记录，并同步样例数据库和可重复执行的 seed SQL；不得把演示 ID 当成生产 `device_id`。
- 默认属性必须与详情页、卡片和业务原型支持的属性一致。用户明确指定默认开关、档位或模式时，SQLite 的 `current_value` 必须同步采用该值。
- 相对路径均以仓库根目录为基准。拒绝把源码写到仓库外部；实际运行数据库是例外，但必须先从代码确认 `DATABASE_PATH`、备份后再修改。

仅在缺失信息会阻止正确实现时提问。设计稿未展示但能从模板和同类页面可靠推断的生命周期、通用卡片行为与主题规则，可以沿用并在交付时说明。设备属性键、取值、控制语义或关键素材无法可靠推断时，必须先询问，禁止编造协议和资源名。

## 优先级

发生差异时按以下顺序处理：

1. 用户当前文字要求和补充说明。
2. 设计图中的视觉、文案、状态和交互表达。
3. 仓库现有公共 UI 组件、主题、字体、国际化和导航模式。
4. 参考模板的生命周期、业务流程和代码组织。
5. 邻近同类模块的实现惯例。

模板与设计稿视觉不一致时，以设计稿为准；模板与目标设备协议不一致时，不得照抄模板协议。

## 执行流程

### 1. 确认边界并保护现有工作

1. 解析目标目录、模块名、目标 `.c/.h` 和模板 `.c/.h` 的完整路径。
2. 检查目标文件是否已存在：
    - 不存在时创建配对文件。
    - 已存在时将任务视为完善现有模块，先读取并做最小修改，不得整文件覆盖或丢失用户改动。
3. 检查工作区相关文件和邻近实现，避免覆盖未提交修改。
4. 除目标模块和完成注册/构建所必需的文件外，不修改无关代码。

### 2. 读取模板与接入链路

至少检查：

- 参考模板的 `.c` 和 `.h`。
- 模板使用的公共页面/卡片创建函数、主题图片加载、字体、国际化、导航和日志接口。
- 模板符号在仓库中的注册表、设备类型映射、函数指针绑定和调用位置。
- 与目标功能更接近的 1～2 个同类模块；参考模板不是最佳业务样例时，组合参考，但不要扩大修改范围。
- 相关 CMake 配置和资源生成方式。仓库通过 GLOB 在配置阶段收集新增 `.c`，新增源码后仍需重新执行 CMake 配置。
- 设备数据恢复链路：`hdl_device` 读取、属性 JSON 解析、空间绑定恢复、收藏恢复，以及程序实际使用的 `DATABASE_PATH`。
- 同类设备在 `db/gui-sample.db`、`docs/sql/gui_mock_devices.sql`、`hdl_space_map` 和 `hdl_favorite` 中的测试数据模式。

先列清目标模块需要保留的公共入口和接入点，再开始编码。不要只复制两个文件却遗漏类型映射、注册、测试数据或运行库部署，导致页面永远不会被调用或程序启动后看不到设备。

### 3. 拆解设计图

在写代码前从设计图提取并记录：

- 画布或页面有效区域、顶部/底部安全区、背景层级。
- 控件树、排列方向、对齐基准和遮挡关系。
- 每个控件的位置、尺寸、间距、内边距、圆角、边框、颜色、透明度和阴影。
- 字号、字重、颜色、行高、对齐、截断方式和文案来源。
- 图片/图标、裁剪方式、旋转、缩放和不同状态资源。
- 默认、按下、选中、开、关、禁用、离线、加载等状态。
- 可点击区域、短按/长按/滑动行为和页面跳转。

不要凭常见手机 UI 习惯改造中控屏设计。不要自行假设屏幕分辨率；从设计图、项目常量、父容器或模板确认坐标系。设计图无法确定的细节应优先遵循同类页面，并将关键假设写入交付说明。

### 4. 复用资源和公共组件

1. 优先使用仓库现有的页面容器、卡片、按钮、滑块、弹窗、返回区域和状态刷新函数。
2. 图片先搜索主题资源注册和既有 `ui_theme_load_image()` 调用，必须使用真实存在的资源键。
3. 字体使用项目 `resource_fonts_style()` 等既有接口；需国际化的文案沿用语言文本接口，不随意硬编码。
4. 颜色、透明度、圆角和尺寸应从设计图精确落值；项目已有语义常量时优先复用。
5. 不用文本字符或 LVGL 符号假装设计图中的专用图片。缺少素材时明确指出缺少的资源、期望尺寸和状态，不编造资源名。
6. 不为了单个页面新增重复的通用组件；确有跨页面复用价值时才抽取，并保持本次改动最小。

### 5. 创建 `.h` 文件

- 使用与目标路径和模块名一致的 include guard。
- 将 LVGL 控件句柄按页面/卡片/状态分组保存在模块私有 UI 结构中，命名随目标模块调整。
- 只声明接入框架确实需要的公共生命周期、状态更新、特殊处理和私有空间管理入口。
- 公共函数签名以模板注册契约为基础；不得因个人偏好改变调用方约定。
- 不暴露仅供 `.c` 使用的辅助函数和状态。

### 6. 创建 `.c` 文件并实现业务

#### 页面与布局

- 先创建父容器，再按控件树顺序创建子对象。
- 显式设置影响设计还原的尺寸、对齐、padding、border、radius、颜色、透明度、字体和状态样式，不依赖不明确的 LVGL 默认值。
- 固定分辨率设计可使用精确坐标；项目已有响应式/公共布局方式时沿用，避免无依据地改成百分比布局。
- LVGL style 的生命周期必须覆盖控件使用期；不得把会失效的局部 style 绑定到长期存活对象。
- 扩大点击区域不得改变视觉尺寸，并应符合设计的交互范围。

#### 交互与协议

- 事件回调先判断事件类型，再校验 `user_data`、设备节点和私有 UI 指针。
- 短点击沿用项目 `ui_app_lv_short_clicked()` 等防误触方式。
- UI 操作只在 UI 线程执行；异步业务通知按项目通知机制切回 UI 线程。
- 使用业务层/设备 UI 封装完成属性读写，不从 `app` 越层访问驱动或平台 SDK。
- 属性 key、数据类型、范围、枚举值和组合下发数量必须来自用户说明、协议定义或目标设备现有实现。
- 用户操作后按项目模式处理乐观刷新、真实设备回包、离线提示和演示模式；不要把模板设备的属性直接套到新设备。
- 滑块、旋钮等连续控件应区分拖动中的视觉反馈和释放后的命令下发，避免每帧发送设备命令，除非协议明确要求实时发送。

#### 状态与生命周期

- 将“创建 UI”“根据模型刷新 UI”“发送控制命令”分成清晰职责，避免在布局代码中散落业务判断。
- 初始化失败要返回正确结果，并清理已创建的局部对象或确保统一反初始化能够安全处理半初始化状态。
- 反初始化删除本模块拥有的 LVGL 对象、timer 和其他资源，并立即将句柄置为 `NULL`。
- 初始化/反初始化应能安全应对重复调用，不产生重复控件、悬空指针或二次释放。
- `private_alloc/private_free` 的分配大小、清零、失败处理和释放方式与目标私有结构严格匹配。
- 页面销毁后不得继续由 timer、异步回调或事件访问其控件。

### 7. 注释与模块说明

创建或完善 LVGL 模块时，注释风格参考 `src/app/device/curtain_switch.c` 和 `src/app/device/curtain_switch.h`，但必须根据目标模块的真实控件、页面和行为编写，禁止照抄窗帘名称、卡片字段或交互语义。

#### `.c` 文件头说明

- 模块同时实现小卡片、大卡片或详情页时，在 include 之前使用普通块注释概述各形态的定位、尺寸、直接操作能力和详情页入口。
- 模块包含收藏页、列表页、常用页等多个卡片实例时，在文件头用注释表格列出“字段、初始化函数、显示位置”，便于追踪同一私有结构在不同页面的用途。
- 表格内容必须来自实际结构字段、注册函数和调用位置；不存在的页面或卡片形态不写，不根据模板臆造。

```c
/*
 * 小卡片用于展示设备摘要，短按卡片进入详情页。
 * 大卡片提供常用控制，也可通过卡片主体进入详情页。
 *
 * 小卡片：144 × 198，见 ui_small_card_create()。
 * 大卡片：296 × 198，见 ui_large_card_create()。
 *
 * | 字段           | 初始化函数                    | 显示位置       |
 * |----------------|-------------------------------|----------------|
 * | fav_small_card | ui_<module>_fav_card_init()   | 收藏管理页面   |
 * | lst_small_card | ui_<module>_lst_card_init()   | 设备列表页面   |
 * | com_small_card | ui_<module>_com_card_init()   | 首页“常用”区域 |
 * | com_large_card | ui_<module>_com_card_init()   | 首页“常用”区域 |
 */
```

示例只表达格式。若目标模块的收藏卡片不进入详情页、大卡片没有直接控制、尺寸不同或只实现部分形态，必须按实际代码改写或省略对应内容。

#### 结构体与字段注释

- `.h` 中每个私有 UI 结构、请求/状态结构和回调类型都使用 Doxygen `@brief` 说明职责。
- 每个结构体字段都使用 `/**< ... */` 说明它对应的控件、状态、页面位置或生命周期用途，不保留无说明字段。
- 聚合私有 UI 结构中的卡片字段应明确所属页面，例如“收藏管理页小卡片”“设备列表页小卡片”“首页常用区域大卡片”。
- 对预留、当前未创建或当前未使用的字段如实注明现状，不虚构用途，也不要为了消除疑问擅自删除模板契约所需字段。
- 字段注释应区分根控件、标签、图像容器、背景图像、左右状态图像、按钮、动画和回调，避免统一写成“控件”或“数据”。

```c
/**
 * @brief 设备小卡片的控件集合。
 */
typedef struct {
    lv_obj_t* card;            /**< 小卡片根控件。 */
    lv_obj_t* card_name;       /**< 设备名称标签。 */
    lv_obj_t* card_space_name; /**< 设备所属空间名称标签。 */
    lv_obj_t* card_icon;       /**< 承载设备图像的图标容器。 */
    lv_event_cb_t event_cb;    /**< 预留的卡片事件回调。 */
} ui_<module>_small_card_t;
```

#### 函数 Doxygen

- `.h` 中所有公共函数声明、`.c` 中对应的公共函数定义、`static` 辅助函数和 LVGL 事件回调都添加完整 Doxygen 注释。
- `@brief` 说明函数实际完成的行为，不只复述函数名；更新已有模块时保留原注释包含的有效信息，并修正与实现明确冲突的描述。
- 每个具名参数必须有且只有一个 `@param`，名称和顺序与函数签名完全一致。
- `@param` 根据实际情况说明输入/输出方向、是否允许为 `NULL`、单位、范围、所有权、生命周期、当前未使用状态，以及 LVGL 事件 `user_data` 的类型和用途。
- 所有非 `void` 函数必须有 `@return`，覆盖成功、失败、固定返回值和特殊返回值；`bool` 返回值明确说明 `true` 与 `false` 的条件。
- `void` 函数不写 `@return`，无参数函数不写 `@param`。
- 头文件声明和源文件定义都要有契约注释；静态前置声明不必与定义重复，但静态函数定义必须有注释。

```c
/**
 * @brief 初始化设备列表页小卡片。
 * @param parent_handle 承载列表页卡片的父控件句柄。
 * @param node 列表页卡片关联的设备节点。
 * @return 父控件和设备节点有效且初始化成功返回 true，否则返回 false。
 */
bool ui_<module>_lst_card_init(void* parent_handle, void* node);

/**
 * @brief 处理设备卡片短按并打开详情页。
 * @param e 卡片的 LVGL 事件，用户数据为设备节点。
 */
static void open_details_event_handler(lv_event_t* e);
```

#### 内部说明与检查

- 函数内部用于解释布局分区、坐标基准、事件冒泡、状态映射、资源生命周期和特殊协议约束的普通注释可以保留，不强制转换为 Doxygen。
- 不添加逐行复述代码的注释；注释重点解释页面归属、控件角色、交互契约和非显然约束。
- 完成后逐项核对：每个结构和字段都有说明；每个函数有 `@brief`；参数与 `@param` 一一对应且顺序一致；所有非 `void` 函数都有准确的 `@return`。

### 8. 完成代码接入

搜索模板模块名和公共入口的全部引用，按目标设备实际需求更新对应位置，例如：

- `src/business/device/device_type.h` 中的设备类型或 SPK 类型。
- `src/business/device/protocol.c/.h` 中的协议枚举、SPK 映射和属性通知分发。
- `src/business/device/prototypes.c` 中的业务原型、属性 key、类型、枚举值和范围。
- `src/app/device/protocol.c`、`src/app/device/spk.c` 中的 UI presentation、生命周期、卡片、详情页和特殊处理绑定。
- 目标模块 `.h` include、私有空间申请/释放、属性刷新和页面打开入口。
- 主题资源、资源声明和资源构建清单。

具体文件名可能随仓库演进变化，必须通过搜索同类 SPK 和模板入口确认，不能只按清单机械修改。完成后反向搜索新模块名、SPK、协议枚举和设备类型，确认每条调用链都可达。

如果用户要求新增完整设备，默认实现收藏管理小卡片、设备列表小卡片、常用小卡片、常用大卡片和详情页；设计或协议明确不需要某一形态时才省略，并在交付时说明。若用户明确只要孤立原型，则说明它未注册、未写入数据库且运行时不可见。

### 9. 接入专用图片资源

新增设备缺少专用图标时，不能长期以其他设备素材冒充完成状态：

1. 优先使用从 Figma、Sketch 或 PSD 导出的独立 RGBA 透明 PNG，不直接使用包含多个设备的总览图或截图。
2. 根据小卡片、大卡片及开关状态确认需要 2 张还是 4 张素材；图案不随开关变化时，可复用图片并通过透明度表达状态。
3. 核实项目的 LVGL 主版本、`LV_COLOR_DEPTH` 和既有生成文件格式。LVGL 8 应生成 `lv_img_dsc_t` 与 `LV_IMG_CF_TRUE_COLOR_ALPHA`，不得混入 LVGL 9 的 `lv_image_dsc_t`。
4. 将生成的图片 C 数组放入 `resource/png/`，在 `resource/cpng.h` 添加 `LV_IMG_DECLARE(...)`，并在 `src/app/setting/theme.c` 注册主题资源键。
5. 业务代码通过 `ui_theme_load_image()` 加载主题键，不直接依赖 `theme01_*` C 符号。
6. 图片变化后先执行 `rebuild_assets`，再构建 `app`。
7. 仓库存在 `docs/关于LVGL图片资源转换与接入.md` 时，先读取并遵循其中的当前参数和排错流程。

素材未提供时允许使用明确标注的临时占位实现，但交付说明必须列出待替换资源、期望尺寸、状态数量和建议资源键，不能声称素材接入已完成。

### 10. 新增 SQLite 演示设备

用户要求“新增设备”而非孤立页面原型时，默认同时创建可运行的演示数据，不等待用户再次提醒：

1. 从 `src/business/def.h` 或数据库初始化代码确认实际 `DATABASE_PATH`，不要假定程序直接读取仓库中的 `db/gui-sample.db`。
2. 检查 `hdl_device`、`hdl_space_map`、`hdl_favorite`、`hdl_space` 的真实表结构、枚举定义和同类记录，不臆造列名或 `relation_type`、`favorite_type` 数值。
3. 在 `db/gui-sample.db` 增加明确的演示设备：
    - `device_id` 使用唯一的 `gui-demo-<device>`；
    - `device_name` 使用“模拟<设备名>”；
    - `spk` 与代码注册值完全一致；
    - `group_id`、`sid`、`attributes_value`、`favorite` 按同类记录和业务语义填写；
    - `attributes` 使用合法 JSON 数组，每个属性包含恢复所需的 `key`、`current_value`、`value`，范围属性按协议补 `min`/`max`；
    - 默认状态与用户要求、卡片视觉和详情页一致。
4. 同步更新 `docs/sql/gui_mock_devices.sql` 或仓库实际 seed SQL，保证样例库可以重复生成；同时更新设备类型数量和分类说明等注释。
5. 添加有效空间映射，使设备能在指定房间的列表中出现。通常使用 `hdl_space_map.relation_id = device_id`，但必须读取 `DAL_RELATION_DEVICE` 的真实枚举值后再写入。
6. 若需要出现在首页“常用/收藏”，还要检查并写入 `hdl_favorite` 的设备记录、类型和排序索引；不要把“房间设备列表可见”和“首页常用可见”混为一谈。
7. 写入前检查相同 `device_id` 或 SPK 演示记录，避免重复；设备、空间映射和收藏修改必须处于同一事务。
8. 没有 `sqlite3` CLI 时使用 Python 标准库 `sqlite3`，不能因此跳过数据库接入。

数据库验证至少包括：

- 精确查询新 `device_id` 和 SPK，确认只有一条；
- 解析并比对属性 JSON、默认开关、档位或模式；
- 检查空间映射以及按需添加的收藏记录；
- 执行 `PRAGMA integrity_check`；
- 在临时数据库副本上完整执行 seed SQL，检查语法、设备总数、唯一 ID 和 JSON 合法性；
- 检查二进制数据库与 seed SQL 的工作区状态，确认两者确实都已修改。

### 11. 同步实际运行数据库

只修改 `db/gui-sample.db` 不代表当前程序会看到新设备。用户要求运行、截图或查看效果时，必须继续完成运行库同步：

1. 查询当前平台实际使用的数据库绝对路径，并确认运行库中是否已有目标 SPK；不要仅验证样例库。
2. 优先使用仓库部署脚本，例如 `script/ssd20x/deploy_sample_db.sh`。脚本会整体替换数据库时，先说明它会影响现有数据。
3. 若只需向本地模拟器运行库加入演示设备，先使用 SQLite 一致性备份，再在事务中插入设备、空间映射和按需收藏记录；不无备份覆盖用户运行库。
4. 在交付说明中给出实际运行库路径、同步方式和备份路径。
5. 设备通常由 `business_device_init()` 在启动时恢复到内存。应用已经运行时，修改 SQLite 后必须停止并重新启动；页面刷新、热重载或重新构建不会自动重新加载设备列表。
6. 检查云设备同步是否会删除本地演示记录。同步启用时使用项目已有离线 GUI 测试方式，或明确说明演示设备可能被云端列表覆盖；不永久破坏生产同步逻辑。
7. 重启后在目标房间设备列表验证；需要常用卡片时，再验证首页收藏/常用区域。设备未收藏时，不承诺它会显示在首页常用区域。
8. 无法访问真机时，完成样例库和 seed SQL 后给出准确部署命令，并明确尚未验证真机运行库。

### 12. 端到端可见性排查

新增设备“编译成功但界面看不到”时，按顺序排查：

1. 当前进程实际使用哪个数据库，运行库中目标 SPK 是否存在。
2. 应用是否在数据库修改后重新启动。
3. `hdl_device.attributes` 是否能被解析，必需属性是否满足业务原型；属性恢复失败会释放设备节点。
4. SPK 是否映射到正确业务协议、设备类型和 UI presentation。
5. 私有空间申请、卡片初始化、详情页和属性通知函数是否已经注册。
6. `hdl_space_map` 是否使用正确的 `device_id`、空间 ID 和设备关系类型。
7. 当前 UI 选择的楼层/房间是否与映射一致。
8. 查看首页常用时，是否存在正确收藏记录；未收藏设备通常只在房间设备列表可见。
9. 云同步、恢复出厂或 seed SQL 是否在启动后删除或覆盖了演示记录。
10. 启动日志是否出现“属性恢复失败”“设备不存在”“无效 SPK”或资源键为空。

### 13. 视觉自检

逐项对照设计图检查：

- 页面整体尺寸、视觉中心和主次层级。
- x/y、宽高、间距、padding 和对齐基准。
- 圆角、边框、颜色、透明度、字体和图片状态。
- 文案、单位、数值格式、截断和空状态。
- 默认、按下、开关、禁用、离线及切换后的视觉。
- 点击区域、事件冒泡、滑动冲突和返回行为。

如果仓库有可运行的模拟器或截图对比流程，构建并运行它进行截图复核；没有可用截图工具时，明确说明只完成代码级视觉核对，不得声称像素级截图一致。

### 14. 格式化与验证

1. 仅对本次修改的 C/H 文件运行根目录 `.clang-format`。
2. 新增 `.c` 后重新执行 CMake 配置，使 GLOB 收集到新文件。
3. 构建受影响目标；涉及 PNG C 资源变化时先运行 `rebuild_assets`。
4. 按 `embedded-layer-architecture` 技能要求运行架构检查。
5. 检查编译告警、未声明符号、无效资源键、未使用函数、注册遗漏和头文件依赖。
6. 验证数据库记录、属性 JSON、空间映射、收藏、seed SQL 和 `PRAGMA integrity_check`。
7. 对照样例库与实际 `DATABASE_PATH`，确认运行库已经同步；应用已启动时重启再验证。
8. 在目标房间验证列表卡片；需要常用卡片时验证收藏和大小卡片；打开详情页验证默认状态、控制、失败回滚和属性回刷。
9. 运行项目 diagnostics 和 `git diff --check`，检查所有目标文件的工作区状态。
10. 环境缺少 LVGL、预编译库、图形依赖、数据库权限或真机连接时，报告实际失败命令和阻塞原因，不得谎称验证通过。

## 完成定义

新增完整设备只有同时满足以下条件才算完成：

- `.c/.h` 页面与要求的卡片形态已实现；
- SPK、设备类型、协议、业务原型、属性通知和 UI 生命周期已注册；
- 专用资源已接入，或明确记录仍待提供的素材；
- 样例数据库和 seed SQL 已加入演示设备、默认属性及空间映射；
- 按需求完成收藏/常用数据；
- 实际运行数据库已同步，或因无法访问目标设备而提供准确部署步骤；
- 应用在数据库修改后已经重启；
- 目标房间设备列表可以看到设备，详情页可以打开并正确显示默认状态；
- 构建、架构检查、数据库完整性和实际可见性验证均有真实结果。

## 禁止事项

- 不看 `.h`、注册点和调用链就整文件复制模板。
- 不从设计图臆造设备协议、属性 key、资源名或页面跳转。
- 不用大量魔法偏移补偿错误父子层级；先确认正确对齐基准。
- 不用动态创建而不释放的临时 style、timer、动画回调或遮罩。
- 不在非 UI 线程直接调用 LVGL。
- 不为追求“看起来接近”而忽略按下态、开关态、禁用态和真实状态回刷。
- 不覆盖目标已有代码，不顺手重构无关页面，不修复无关历史问题。
- 不把只修改样例数据库描述成已经修改运行库，不把数据库写入描述成应用内存已经刷新。
- 不在未备份时覆盖实际运行数据库，不用演示 ID 冒充生产设备 ID。
- 不混淆设备空间映射与场景映射，也不混淆设备列表可见与首页收藏/常用可见。
- 不仅因为编译通过就宣称与设计图一比一；视觉一致性必须逐项对照，最好有运行截图验证。
