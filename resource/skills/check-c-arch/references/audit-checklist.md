# 架构审查清单

本清单从项目代码质量规范中提取会影响模块边界、替换能力、线程安全和独立构建的结构性规则。普通排版和命名问题不属于本技能报告范围。

## 1. 单向分层

```text
app -> business -> hal -> drivers
app/business/hal/drivers -> pkg
```

检查所有依赖载体：

- `#include` 和传递包含；
- 直接符号调用和全局对象；
- 函数参数、结构体字段、返回值和回调签名中的类型；
- 宏与编译定义；
- CMake 的链接目标、include 目录和源码聚合。

重点违规模式：

- app 直接包含、调用或链接 hal/drivers；
- business 绕过 hal 调用 drivers；
- hal/drivers 反向调用业务或 UI；
- 独立 driver 单元相互包含或链接；
- pkg 依赖产品业务层、硬件层或 LVGL。

## 2. 职责归属

| 代码性质 | 所有者 |
| --- | --- |
| 页面、控件、导航、LVGL、UI 状态、UI 线程调度 | app |
| 用例、业务校验、领域状态、重试/降级策略、业务事件 | business |
| 持久化、序列化、查询结果转换 | business/dal |
| 平台无关的硬件能力、统一能力类型 | hal |
| Linux/芯片/开发板/厂商 SDK 的具体操作 | drivers |
| 与产品、UI、特定硬件都无关的基础能力 | pkg |

判断方法：

1. 替换 LVGL 后仍成立的规则通常不应留在 app 控件实现中。
2. 更换开发板后仍成立的能力放 hal，平台调用放 drivers。
3. app 发起硬件操作仍须由 business 提供用例接口。
4. 跨设备编排放 hal，不放入某个 driver。
5. 下层触发上层时返回数据或发布下层拥有的事件，不包含上层头。

## 3. 公共接口和类型所有权

- API 提供层拥有请求、结果、状态、事件和回调类型。
- business 不公开 LVGL 类型，hal 不公开 driver 结果/句柄，drivers 公共头不公开不必要的 SDK 类型。
- 跨层结构使用 `bool`、定宽整数、枚举、字节缓冲区和语义明确的值对象。
- 公共 `<name>.h` 只声明调用方所需接口；`<name>_priv.h` 只在同一模块使用。
- 头文件中不得定义可导致多重定义或跨模块直接修改的全局状态。

## 4. 返回值与错误边界

- 单纯成功/失败使用 `bool`。
- 需要区分原因时，由接口提供模块定义自己的 `_result_t`。
- hal/business 将下层结果映射为本层语义，不把 driver 结果类型一路透传。
- drivers 只上报平台/设备错误，不决定产品重启、退出或业务降级。
- business 决定重试、降级或终止用例；app 只映射最终界面反馈。

报告时关注跨层错误职责，不报告普通遗漏返回值，除非它破坏资源、状态或架构契约。

## 5. 回调、通知和 UI 线程

回调接口应明确：

- 单处理器还是多订阅者，后注册是否覆盖；
- `NULL` 是否注销；
- 同步/异步、执行线程和重入规则；
- 载荷所有权与有效期；
- 注销和并发发布的生命周期；
- 调用外部回调时的锁边界。

business 更新 UI：

1. 事件、载荷和处理器类型由 business 定义。
2. app 注册处理器，business 不包含 app 头文件。
3. 同步处理器运行在发布线程；借用数据至少在回调返回前有效。
4. 非 UI 线程的 app 处理器只复制数据并调用 `ui_app_notify_post()`。
5. 最终仅在 UI 线程操作 LVGL。
6. 调用外部处理器前释放 business 内部互斥锁。

## 6. 宏和定义所有权

- 宏由提供模块维护，消费方不复制同值常量。
- 跨层宏引用仍须遵守依赖方向。
- 跨本层多个模块放 `src/<layer>/<layer>_def.h`。
- 同模块多个文件放 `<module>/<module>_def.h`，不得被其他模块包含。
- 单个 `.c` 使用的常量留在实现文件，优先匿名 `enum` 或 `static const`。
- `pkg` 不得为了共享宏而承载产品业务、特定硬件或 UI/LVGL 定义。

## 7. 驱动、平台和构建

- drivers 按能力组织，不按页面组织。
- SSD20x 专属实现使用 `ssd20x_` 前缀，x86 使用 `x86_` 前缀，共享实现不加平台前缀。
- app LVGL 端口沿用 `lvgl_port_<platform>.c` 后缀规则，不与 driver 前缀规则混用。
- 构建系统对同一接口只选择当前平台实现，避免重复定义。
- 分层目标只公开必要 include 目录，并按 `app -> business -> hal -> drivers` 链接。
- driver 目标应能仅依赖自身公共头、pkg 和平台依赖独立构建。
- 历史顶层聚合或直接链接是待迁移问题，不是新增越层的许可；全仓检查时可报告为历史架构债务。

## 8. 误报排除

最终确认前排除：

- 注释和字符串中的符号；
- 第三方或生成代码；
- 仅资源格式声明使用 LVGL 的静态 resource 文件；
- 测试替身和明确隔离的 host mock；
- 条件编译中不会进入当前目标的实现，但仍需核实是否在其他受支持平台违规；
- 名称相同但所有者不同的宏或函数。
