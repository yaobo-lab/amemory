# VLAN 虚拟局域网：网络隔离利器 —— 学习笔记（完整版）

## 引入：一个"困惑"现象

真实场景：一台 48 口交换机同时接了销售部和技术部的 PC，结果：

```
        一台 48 口交换机
   ┌────────────┼────────────┐
 销售部PC      技术部PC       │
   │            │            │
   └──ping不通──┘  ← 明明插在同一台交换机上！
   同部门PC之间却正常通信
```

- 这不是故障，而是 **VLAN** 在起作用
- 交换机被"切"成多个逻辑局域网；不同 VLAN 之间 **二层隔离**，必须走 **三层路由** 才能互通
- 在 VoIP 组网中 VLAN 是标配：**语音流量和数据流量走不同 VLAN**，互不干扰

---

## 一、VLAN 是什么？逻辑上的"隔板"

### 1.1 核心概念：一台物理交换机 = 多个逻辑广播域

类比：一栋大楼只有一层（一台交换机），用隔板分出多个房间（多个 VLAN）；同房间的人能互聊（同 VLAN 互通），不同房间听不到彼此（跨 VLAN 隔离），交流要走走廊（三层路由）。

没有 VLAN 的后果：所有设备在同一广播域，一台 PC 发 ARP 广播全网都要处理 → **广播风暴、安全问题、带宽浪费**。

```
┌──────────────────────────────────────────┐
│           物理交换机（一台）              │
│  ┌───────────────────────┐               │
│  │ VLAN 10（销售部）      │   802.1Q Tag │
│  │  PC-A1  PC-A2  PC-A3  │  ┌─────────┐ │
│  │  192.168.10.1~3       │──│4字节标签 │ │
│  │  同VLAN可互通          │  │含VLAN ID │ │
│  └───────────────────────┘  │插入帧头  │ │
│  ┌───────────────────────┐  └─────────┘ │
│  │ VLAN 20（技术部）      │               │
│  │  PC-B1  PC-B2  PC-B3  │               │
│  │  192.168.20.1~3       │               │
│  └───────────────────────┘               │
└──────────────────────────────────────────┘
 VLAN10 ↔ VLAN20：二层不可互通，需三层路由
 一台物理交换机 = 两个逻辑独立的广播域
```

### 1.2 802.1Q Tag：隔离的"身份证"

- 底层机制：**IEEE 802.1Q 标签**
- 交换机在以太网帧头插入 **4 字节 Tag**，内含 **VLAN ID（12 位，支持 1~4094 个 VLAN）**
- 交换机按 Tag 判断帧归属，只在同一 VLAN 内转发

转发举例：

```
PC-A1(VLAN10) → PC-A2(VLAN10):
  收帧 → 打上VLAN10的Tag → 查MAC表(仅限VLAN10端口) → PC-A2收到 ✔

PC-A1(VLAN10) → PC-B1(VLAN20):
  目标MAC不在VLAN10范围内 → 直接丢弃 / 走三层路由 ✘(二层)
```

## 二、三种端口类型：Access / Trunk / Hybrid

端口类型决定交换机如何处理 Tag，适用不同连接场景。

```
┌─────────────┬─────────────────┬──────────────────────┐
│ Access端口   │ Trunk端口        │ Hybrid端口            │
│ 连接终端设备  │ 连接交换机之间    │ 灵活混合模式           │
├─────────────┼─────────────────┼──────────────────────┤
│·只属于1个VLAN│·属于多个VLAN     │·多VLAN成员            │
│·收帧:加Tag   │·收发带Tag帧      │·可选Tag/Untag         │
│·发帧:去Tag   │·PVID=Native VLAN│·按VLAN决定            │
│·对终端透明   │·允许VLAN列表     │·最灵活                │
├─────────────┼─────────────────┼──────────────────────┤
│ PC→SW       │ SW1←→SW2        │ 话机→SW               │
│ 无Tag       │ 带Tag(多VLAN复用)│ 语音VLAN带Tag          │
│             │                 │ 数据VLAN去Tag          │
├─────────────┼─────────────────┼──────────────────────┤
│配置:         │配置:             │配置:                  │
│port link-   │port link-type   │port link-type hybrid  │
│ type access │ trunk           │port hybrid tagged     │
│port default │port trunk permit│ vlan 20               │
│ vlan 10     │ vlan 10 20 30   │port hybrid untagged   │
│             │                 │ vlan 10               │
├─────────────┼─────────────────┼──────────────────────┤
│用于:接PC/话机│用于:SW级联/上行  │用于:话机+PC混接        │
└─────────────┴─────────────────┴──────────────────────┘
```

| 端口类型 | Tag 处理 | 连接对象 | VoIP 场景 |
|---|---|---|---|
| Access | 收加 Tag，发去 Tag | 终端设备（PC/单话机） | 纯话机或纯 PC 端口 |
| Trunk | 带 Tag 收发 | 交换机之间 | 核心—接入交换机级联 |
| Hybrid | 按 VLAN 选 Tag/Untag | 话机+PC 混接端口 | 语音 Tagged + 数据 Untagged |

**VoIP 黄金组合**：接入层用 **Hybrid 端口** —— 语音 VLAN 带 Tag（话机能识别）、数据 VLAN 去 Tag（PC 无需感知 VLAN），是 VoIP 组网最常见的端口配置方式。

## 三、VLAN 间通信：隔离不是永别

跨 VLAN 通信（如话机访问数据 VLAN 的文件服务器）需要 **三层路由**，两种方案：

```
方案A：单臂路由(Router-on-a-Stick)   │  方案B：三层交换机(L3 Switch)
                                      │
  路由器(子接口G0/0.10、G0/0.20)      │   ┌──────────────────────┐
   │Trunk                             │   │ 三层交换机            │
  二层交换机(VLAN10+VLAN20)           │   │ VLAN10:192.168.10.254│
   │            │                     │   │ VLAN20:192.168.20.254│
 PC-A(VLAN10)  PC-B(VLAN20)           │   └──────┬─────────┬─────┘
                                      │     PC-A(VLAN10) PC-B(VLAN20)
通信流程(VLAN10→VLAN20):              │  通信流程:
1.PC-A发现目标在别的网段              │  1.PC-A发现目标在别的网段
2.发给网关(路由器子接口)              │  2.发给VLAN10网关
3.交换机打Tag10→路由器                │  3.首包三层查路由表→出接口VLANIF20
4.路由器剥Tag10→查路由表              │  4.查VLAN20的ARP表→重新封装Tag20
5.重新打Tag20→交换机                  │    →二层转发PC-B
6.交换机去Tag→PC-B收到                │  5.生成FIB表项
缺点:路由器单点、带宽瓶颈             │  6.后续流量走硬件交换
                                      │  优点:高性能、无单点瓶颈
```

| 对比项 | 单臂路由 | 三层交换机 |
|---|---|---|
| 核心设备 | 路由器 + 二层交换机 | 三层交换机（二合一） |
| 转发方式 | 每个包都走路由器 | 首次路由后硬件交换 |
| 性能 | 较低（路由器是瓶颈） | 高（ASIC 硬件转发） |
| 成本 | 中 | 中高（三层交换机较贵） |
| VoIP 推荐 | 小型组网/临时方案 | 中大型 VoIP 组网首选 |

**三层交换机举例**：SW 上 VLAN10 接口 IP=192.168.10.254，VLAN20 接口 IP=192.168.20.254；PC-A 网关 .10.254，PC-B 网关 .20.254。PC-A→PC-B：收帧 → 查路由表 → 硬件转发到 VLAN20；后续同流的包直接二层交换 —— **一次路由，多次交换**，性能极高。

## 四、LLDP / CDP：邻居发现协议

话机如何知道该加入哪个 VLAN？两条主流路径：

```
路径一：邻居发现协议(LLDP-MED / CDP) — 交换机二层主动告知话机语音VLAN
路径二：DHCP Option 132 — 话机先在数据VLAN发DHCP，服务器响应中
        携带语音VLAN ID，话机据此切换
```

### LLDP vs CDP 对比

```
┌────────────────────────┬────────────────────────┐
│ LLDP (IEEE 802.1AB)    │ CDP (Cisco私有)         │
│ 标准协议,跨厂商通用      │ 仅限Cisco设备           │
├────────────────────────┼────────────────────────┤
│ 交换机A←LLDPDU→交换机B  │ 交换机A←CDP帧→交换机B   │
│ (Cisco←→华为/H3C)      │ (Cisco←→Cisco)         │
│ 组播01-80-C2-00-00-0E  │ 组播01-00-0C-CC-CC-CC  │
│ 每30-120秒发一次        │ 默认60秒发一次          │
├────────────────────────┼────────────────────────┤
│ LLDPDU携带的TLV:        │ CDP携带的信息:          │
│ ·Chassis ID:MAC/序列号  │ ·Device ID:主机名       │
│ ·Port ID:端口名/编号    │ ·Addresses:IP地址       │
│ ·TTL:存活时间(默认120秒)│ ·Port ID:出端口         │
│ ·Port Desc:端口描述     │ ·Capabilities:路由/交换 │
│ ·System Name:主机名     │ ·Platform:硬件型号      │
├────────────────────────┼────────────────────────┤
│ 优点:跨厂商通用/标准开放 │ 优点:信息丰富/Cisco原生 │
│ 支持VoIP话机自动发现     │ 默认开启、即插即用      │
│ 支持MED扩展(优先级/VLAN) │ 支持VoIP话机接入发现    │
│ 查询:show lldp neighbors│ 查询:show cdp neighbors │
└────────────────────────┴────────────────────────┘
```

| 对比项 | LLDP | CDP |
|---|---|---|
| 标准 | IEEE 802.1AB（国际标准） | Cisco 私有 |
| 跨厂商 | 支持（华为/H3C/Cisco 等） | 仅限 Cisco 设备间 |
| 发送周期 | 30–120 秒 | 60 秒（默认） |
| VoIP 扩展 | LLDP-MED（语音 VLAN/QoS） | CDP（语音 VLAN ID） |
| VoIP 推荐 | 多厂商环境首选 | 纯 Cisco 环境 |

### LLDP-MED：VoIP 的关键扩展

不仅发现邻居，还能向话机下发网络策略："你的语音 VLAN 是 10，QoS 优先级是 46（DSCP EF）"。话机收到后自动加入正确 VLAN，无需手动配置，实现真正的 **"零配置部署"**。

### 排错实战

```
现象：话机接入后不获取语音VLAN的IP，反而在数据VLAN拿了IP
排查：show lldp neighbors → 话机不在邻居列表 → 端口LLDP未开启！
解决：端口开启 lldp tx/rx → 话机收到LLDP-MED策略 → 自动切到语音VLAN
     → 获取语音IP → 注册成功 ✔
备选：交换机不支持LLDP-MED时，用DHCP Option 132
     （话机通过DHCP响应获取语音VLAN ID，同样自动切换）
```

## 五、VLAN 中 DHCP 工作：跨 VLAN 获取 IP

问题：DHCP Discover 是 **广播包**，只在同一 VLAN 内传播；DHCP 服务器在别的 VLAN 时广播过不去 → 需要 **DHCP Relay（中继代理）**。

```
 VLAN 10网段                三层交换机                 DHCP服务器
┌────────────────┐   广播  ┌─────────────────┐ 单播(中继)┌──────────────┐
│PC(192.168.10.x)│───────→│VLAN10接口(网关)   │─────────→│ 10.1.1.100   │
│DHCP Discover   │        │启用DHCP Relay     │          │VLAN10池:     │
│(广播)          │        │ip relay-address   │          │ .10.100-.200 │
└────────────────┘        │ 10.1.1.100        │          │VLAN20池:     │
                          └─────────────────┘          │ .20.100-.200 │
                                                       └──────────────┘

完整流程（4步）：
Step1 Discover      Step2 Relay中继      Step3 Offer        Step4 完成
PC广播DHCP Discover 交换机收广播         服务器分配IP        Request→Ack
0.0.0.0→255.255...  转单播→DHCP服务器   通过Relay回给PC     PC获取IP
```

**DHCP Relay 工作原理**：三层交换机收到 VLAN10 的广播 Discover → 封装成 **单播** 转发给服务器（10.1.1.100），同时附加 **Option 82** 告知"请求来自 VLAN10" → 服务器从 VLAN10 地址池分 IP → 经 Relay 单播回 PC。

**Option 82（中继代理信息）**：

| 项 | 内容 |
|---|---|
| 作用 | Relay 转发时附加"哪个端口、哪个 VLAN 来的"信息 |
| 内容 | Circuit ID（接入端口/VLAN 标识）+ Remote ID（交换机标识） |
| 价值 | 服务器知道"请求来自 VLAN10 端口 5"，按 VLAN 分配合适 IP |
| VoIP 场景 | 话机经 LLDP-MED/Option 132 加入语音 VLAN → 发 DHCP → Relay 带 Option 82 → 按语音池分 IP |

**注**：同 VLAN 内 DHCP 直接响应无需 Relay；跨 VLAN 必须配 DHCP Relay（`ip helper-address` / `ip relay-address`）。
