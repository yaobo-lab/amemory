# VoIP 系列 · 第1篇｜IP地址全解：IPv4 与 IPv6 的那些事

> 主线问题：一通 IP 电话 0.1 秒接通，靠的是什么？—— **IP 地址**，即网络世界里每台设备的"门牌号"。没有它，数据包不知道发给谁，话机不知道注册到哪台服务器，通话无法建立。

---

## 一、IP 地址到底是什么

- **定义**：分配给网络中每台设备的**唯一逻辑地址**
- 解决两个核心问题：
  1. **我是谁** —— 标识本机在网络中的位置
  2. **怎么找到我** —— 让其他设备能向自己发送数据
- **类比**：邮政系统的"收件地址"（数据包 = 快递，IP = 地址）
- **关键区分**：

```
  IP 地址  = 逻辑地址（可变）   → 类比：门牌号（搬家可变）
  MAC 地址 = 物理地址（出厂固定）→ 类比：身份证号（终身不变）
```

---

## 二、IPv4：32 位的经典方案

- 1981 年定稿，至今使用最广泛；地址长度 **32 位二进制**，用**点分十进制**表示

### 2.0 地址结构

```
        IPv4 地址 = 32 位二进制，分 4 段，每段 8 位
+-----------+-----------+-----------+-----------+
| 11000000  | 10101000  | 00000001  | 01100100  |
|  = 192    |  = 168    |   = 1     |  = 100    |
+-----------+-----------+-----------+-----------+
                ↓ 点分十进制
              192.168.1.100
   取值：每段 0~255，共 2^32 ≈ 43 亿个地址

  结构划分：
+----------------------+------------------------+
|   网络位 (Network)    |    主机位 (Host)        |
| "在哪个网络" 192.168.1 | "网络中哪台设备" .100   |
+----------------------+------------------------+
```

### 2.1 地址分类：A / B / C / D / E 五类

按网络位与主机位比例划分，常用 A、B、C 三类：

```
类别   网络位   主机位   地址范围                        默认掩码
──────────────────────────────────────────────────────────────────
 A     8 位     24 位    1.0.0.0 ~ 126.255.255.255     255.0.0.0     (/8)
 B     16 位    16 位    128.0.0.0 ~ 191.255.255.255   255.255.0.0   (/16)
 C     24 位    8  位    192.0.0.0 ~ 223.255.255.255   255.255.255.0 (/24)

私有地址（RFC 1918）—— 内网专用，不可直接上公网：
 A 类私有：10.0.0.0    ~ 10.255.255.255    (10/8)
 B 类私有：172.16.0.0  ~ 172.31.255.255    (172.16/12)
 C 类私有：192.168.0.0 ~ 192.168.255.255   (192.168/16)
```

### 2.2 子网掩码：网络位与主机位的"分界线"

作用：告诉设备 IP 里**前多少位是网络号，后多少位是主机号**。

```
举例：IP 192.168.1.100，掩码 255.255.255.0（简写 /24）

  255.255.255.0 = 11111111.11111111.11111111.00000000
                  |<--- "1" = 网络位 --->|| 主机位 = "0" |

  → 前 24 位是网络号（192.168.1），后 8 位是主机号（.100）
  → 可容纳 2^8 - 2 = 254 台设备（去掉网络地址和广播地址）
```

### 2.3 私有地址与 NAT

- 家里 WiFi 总是 `192.168.x.x` 或 `10.x.x.x`，因为它们是 RFC 1918 规定的**私有地址**，任何内网可自由使用、无需申请
- 私有地址**不能直接上公网**（公网路由器直接丢弃），内网设备上网靠 **NAT（网络地址转换）**

```
                   NAT 工作流程：内网如何访问公网

┌────────────┐  源IP: 192.168.1.100  ┌───────────┐  源IP: 203.0.113.5  ┌────────────┐
│  内网 PC    │ ───────────────────→ │ NAT 路由器 │ ───────────────────→ │ 公网服务器  │
│192.168.1.100│                      │  (网关)    │                      │   8.8.8.8   │
└────────────┘                      └─────┬─────┘                      └────────────┘
                                          │
                          NAT 转换表（示例）：
        ┌───────────────────────────┬──────────────────────────┬──────────────┐
        │ 内网 IP:端口               │ 转换为公网 IP:端口         │ 目标 IP:端口  │
        ├───────────────────────────┼──────────────────────────┼──────────────┤
        │ 192.168.1.100:5001        │ → 203.0.113.5:8001       │ 8.8.8.8:80   │
        │ 192.168.1.101:5002        │ → 203.0.113.5:8002       │ 8.8.8.8:443  │
        │ 192.168.1.100:5003        │ → 203.0.113.5:8003       │ 1.1.1.1:80   │
        └───────────────────────────┴──────────────────────────┴──────────────┘
  核心原理：多个内网 IP 共享一个公网 IP，靠【端口号】区分不同连接
  203.0.113.5 是路由器的 WAN 口地址
  回程流量：路由器查表 → 还原内网 IP:端口 → 转发给对应 PC
```

- **生活类比**：NAT = 写字楼前台。各办公室（内网设备）有内线号（私有 IP），对外由前台统一用公网号码（公网 IP）拨出，通过"分机号"（端口号）区分；对方回拨时前台按分机号转接，外人只知道楼的公网号码。

## 三、IPv6：128 位的未来

### 3.1 为什么需要 IPv6

- IPv4 仅约 43 亿个地址，**2019 年 2 月全球 IPv4 地址池正式耗尽**
- NAT 只能延缓危机；物联网、5G、万物互联让每台设备都要 IP
- IPv6：32 位 → **128 位**，总量 2^128 ≈ **3.4 × 10³⁸**，相当于地球每平方米可分配 6.5 × 10²³ 个地址——"够给每粒沙子分一个"

### 3.2 地址结构：冒号分隔十六进制，8 组 × 16 位

```
+-------+-------+-------+-------+-------+-------+-------+-------+
| 2001  | 0db8  | 85a3  | 0000  | 0000  | 8a2e  | 0370  | 7334  |
| 组1   | 组2   | 组3   | 组4   | 组5   | 组6   | 组7   | 组8   |
+-------+-------+-------+-------+-------+-------+-------+-------+
              ↓ 完整表示（冒号分隔）
  2001:0db8:85a3:0000:0000:8a2e:0370:7334
              ↓ 缩写
  2001:db8:85a3::8a2e:370:7334
```

**缩写规则**：

```
  1. 每组前导零可省：0db8 → db8，0370 → 370
  2. 连续全零组用 :: 代替：0000:0000 → :: （整个地址只能用一次）
  3. 总量：2^128 ≈ 3.4 × 10^38

举例：
  完整地址        2001:0db8:85a3:0000:0000:8a2e:0370:7334
  ① 省前导零     2001:db8:85a3:0:0:8a2e:370:7334
  ② 连续零用 ::  2001:db8:85a3::8a2e:370:7334
  （即 ipconfig / ifconfig 里看到的格式）
```

### 3.3 IPv6 地址类型

| 类型 | 前缀 | 说明 | 类比 |
|---|---|---|---|
| 单播 Unicast | `2000::/3` | 一对一通信，全球唯一地址 | 你的手机号 |
| 组播 Multicast | `FF00::/8` | 一对多，发给一组设备 | 群发短信 |
| 任播 Anycast | 取自单播范围 | 发给"最近"的一台设备 | 打 114 查号 |
| 链路本地 | `FE80::/10` | 仅限同一链路内通信 | 同一办公室内线 |
| 唯一本地 | `FD00::/8` | 内网专用，类似 IPv4 私有地址 | 大楼内部号 |

## 四、IPv4 vs IPv6 对比表

| 对比项 | IPv4 | IPv6 |
|---|---|---|
| 地址长度 | 32 位 | 128 位 |
| 地址数量 | 约 43 亿 | 约 3.4×10³⁸ |
| 表示方式 | 点分十进制 `192.168.1.1` | 冒号十六进制 `2001:db8::1` |
| 是否需要 NAT | 需要（地址不够） | 不需要（地址充足） |
| 广播 | 支持广播 | 取消广播，用组播替代 |
| 安全性 | IPSec 可选 | IPSec 内置（强制支持） |
| 配置方式 | DHCP 或手动 | SLAAC 自动配置 + DHCPv6 |
| 头部大小 | 20~60 字节（可变） | 40 字节（固定） |

> **核心差异**：IPv6 不只是"地址更多"，设计上有大量改进——取消广播（减少网络噪声）、内置 IPSec（提升安全性）、简化头部（提升转发效率）、无状态自动配置（即插即用）。

## 五、在 VoIP/SIP 中的实际应用

### 5.1 组网拓扑与通话流程

```
              VoIP 组网中的 IP 地址分配

┌──────────────────────┐            ┌──────────────────────┐
│ IP 话机 A (分机1001)  │            │ IP 话机 B (分机1002)  │
│ 192.168.1.100 (内网)  │            │ 192.168.1.101 (内网)  │
└───────────┬──────────┘            └──────────┬───────────┘
            │  注册                            │  注册
            └───────────────┐  ┌───────────────┘
                            ▼  ▼
                 ┌───────────────────────┐
                 │      SIP 服务器        │
                 │   192.168.1.10 (内网)  │
                 └───────────┬───────────┘
                             │ 出网流量
                             ▼
                 ┌───────────────────────┐
                 │    NAT 网关 / 路由器   │
                 │ 内:192.168.1.1         │
                 │ 外:203.0.113.5         │
                 └───────────┬───────────┘
                             │ NAT 转换后
                             ▼
                 ┌───────────────────────┐
                 │  公网 SIP 中继/运营商   │
                 │  SIP: 10.10.10.1 (公网)│
                 └───────────────────────┘

通话流程：话机A(192.168.1.100) → SIP服务器(192.168.1.10)
          → NAT(203.0.113.5) → 公网中继(10.10.10.1)
```

### 5.2 实战举例：分机 1001（话机 A）拨打外线电话

```
 ① 话机 A (192.168.1.100) 向 SIP 服务器 (192.168.1.10) 发送 INVITE 请求
 ② SIP 服务器判断为外线呼叫，将请求转发给 NAT 网关 (192.168.1.1)
 ③ NAT 网关把源 IP 从 192.168.1.10 改写为 203.0.113.5，发给公网 SIP 中继 (10.10.10.1)
 ④ 公网中继返回响应 → NAT 网关查表还原 → 转发给 SIP 服务器 → 转发给话机 A

关键点：SIP 信令走 SIP 服务器中转；
        RTP 语音流可能走直连（需 STUN/TURN 辅助穿 NAT）
```

### 5.3 VoIP 中 IP 地址的 3 个关键问题

```
 1. NAT 穿透：内网话机的私有 IP 在公网不可达，SIP 信令中 Contact 字段
    可能携带私有 IP 导致呼叫失败 —— 需要 rport / STUN / TURN 解决
 2. DHCP 分配：话机通常用 DHCP 获取 IP，但 SIP 服务器建议用静态 IP，
    避免地址变化导致注册中断
 3. IPv6 适配：部分新版话机和 SIP 服务器已支持 IPv6，
    纯 IPv6 网络可免去 NAT 穿透的麻烦
```

## 六、一张表总结

| 知识点 | IPv4 | IPv6 |
|---|---|---|
| 位数 | 32 位 | 128 位 |
| 表示 | `192.168.1.100` | `2001:db8::1` |
| 分类 | A/B/C/D/E 类 | 单播/组播/任播 |
| 私有地址 | `192.168.x.x` / `10.x.x.x` | `FD00::/8` / `FE80::/10` |
| NAT | 必需 | 不需要 |
| 子网掩码 | `255.255.255.0` 或 `/24` | `/64`（前缀长度） |
| VoIP 影响 | 需处理 NAT 穿透 | 端到端直连，无穿透问题 |

---

**本篇要点回顾**：IP 地址是 VoIP"找到对方、建立连接"的基础 → IPv4（32 位、点分十进制、A/B/C 分类、子网掩码划分网络/主机位、私有地址靠 NAT 上公网）→ IPv6（128 位、冒号十六进制、缩写规则、五类地址、免 NAT/内置 IPSec/自动配置）→ 在 VoIP 组网中 IP 的分配与流转，以及 NAT 穿透、DHCP、IPv6 适配三大实战问题。
