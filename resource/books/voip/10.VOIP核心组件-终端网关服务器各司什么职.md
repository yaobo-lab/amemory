# VOIP核心组件：终端、网关、服务器各司什么职

---

## 〇、生活类比引入

开一家公司打电话需要三个角色：

```
┌─────────────────────────────────────────────────┐
│  ① 桌上的分机（终端）  —— 员工听和说的工具        │
│  ② 总机交换机（服务器）—— 接线、记录、转接        │
│  ③ 外线接口（网关）    —— 内线连到外部电话网      │
└─────────────────────────────────────────────────┘
```

映射到 VoIP 世界：
- **终端** = IP话机 / 软电话
- **服务器** = SIP服务器 / IP-PBX
- **网关** = 连接传统电话网的翻译设备

## 一、三大核心组件：各管一摊

一句话定位：
- **终端（Terminal）**：声音的入口与出口——采集/播放语音、编解码、跑 SIP 协议（＝手脚）
- **服务器（Server）**：系统的大脑——注册、寻址、路由、媒体处理与业务（IVR/会议/计费）
- **网关（Gateway）**：翻译官——把 VoIP（IP网络）与传统电话网（PSTN/模拟/数字中继）连起来

```
                VoIP 三大核心组件全景
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ ① 终端        │   │ ② 服务器      │   │ ③ 网关        │
│ Terminal     │──>│ Server       │──>│ Gateway      │
│ 声音入口出口  │   │ 通信的大脑    │   │ 连接传统电话网│
├──────────────┤   ├──────────────┤   ├──────────────┤
│ IP话机(硬话机)│   │ SIP服务器/    │   │ 模拟网关      │
│ 软电话        │   │   IP-PBX     │   │  (FXS/FXO)   │
│ (MicroSIP等) │   │ 注册/代理/路由│   │ 数字网关      │
│ 模拟话机+ATA │   │ 媒体/会议服务 │   │  (E1/T1)     │
│ 视频/会议终端 │   │ 应用(IVR/计费)│   │ 中继网关      │
│              │   │              │   │  (SIP→PSTN)  │
│              │   │              │   │ SBC边界控制器 │
└──────────────┘   └──────────────┘   └──────────────┘
```

## 二、终端：声音的入口与出口

终端离用户最近，同时干三件事：**采集/播放语音、编解码（压缩）、跑 SIP 协议**（注册、发起呼叫）。

### 2.1 IP 话机（硬话机）
- 专用语音硬件，插网线即用
- 内置扬声器、麦克风、屏幕、SIP 客户端
- 支持 **PoE 供电**（一根网线同时供电+联网）
- 企业办公最常见，是"零配置启动"的主角

### 2.2 软电话（Softphone）
- 装在电脑/手机上的软件：MicroSIP、X-Lite、EyeBeam
- 用设备声卡+网卡通话，**免硬件成本**
- 适合居家办公、呼叫中心座席
- 优点：灵活便宜；缺点：依赖电脑环境（网络抖动、系统资源）

### 2.3 模拟话机 + ATA
- 老座机不能直接连 IP 网，需 **ATA（模拟电话适配器）**
- 一端 RJ11 接普通电话，一端 RJ45 接网络；ATA 负责模拟信号数字化并跑 SIP
- 适合"不舍得换老话机"场景，也用于传真机、POS 机

### 2.4 视频终端 / 会议终端
- 语音基础上增加摄像头与视频编解码，支持视频通话和多方会议
- 常见于会议室（Poly、Yealink、Fanvil 等）

### 终端家族对比

```
┌────────────┬────────────┬────────────┬────────────┐
│  IP话机     │  软电话     │ 模拟话机+ATA│ 视频/会议   │
├────────────┼────────────┼────────────┼────────────┤
│ √ 专业稳定  │ √ 零硬件成本│ √ 旧设备复用│ √ 音视频一体│
│ √ PoE供电  │ √ 灵活便携  │ √ 兼容传真  │ √ 多方会议  │
│ × 需购硬件  │ × 依赖电脑  │ × 需加ATA   │ × 带宽高    │
├────────────┼────────────┼────────────┼────────────┤
│ 适用:办公坐席│ 适用:居家坐席│ 适用:老座机  │ 适用:会议室 │
│ 跑SIP+编解码│ 用声卡采集   │ ATA做转换   │ 含编码协商  │
│ 屏幕/按键   │ MicroSIP等  │ RJ11→RJ45  │ 摄像头+屏   │
│ 企业首选    │ 轻量首选    │ 平滑迁移    │ 协作利器    │
└────────────┴────────────┴────────────┴────────────┘
一句话：IP话机=专人专岗稳定专业；软电话=灵活零成本依赖电脑；
        ATA=旧物利用兼容老设备；视频终端=开会神器带宽要求高
```

## 三、网关：连接两个世界的"翻译官"

- VoIP 跑 IP 网络，PSTN 跑电路交换网络，两套体系**语言不通**，网关就是翻译。
- **为什么必须网关**：员工用 SIP 话机打客户手机（走运营商 PSTN），必须把 SIP 呼叫"翻译"成 PSTN 能识别的中继信号——这一步只能由网关完成。

### 3.1 网关做的两件事
1. **协议转换**：SIP（IP 侧）↔ 七号信令/ISDN PRI（PSTN 侧）
2. **编解码转换（Transcoding）**：IP 侧 G.711/G.729 ↔ PSTN 侧 PCM 时隙，实时转换

### 3.2 常见网关类型

```
┌──────────┬────────────────┬───────────────────┬──────────────┐
│ 类型      │ 连接对象        │ 接口               │ 典型用途      │
├──────────┼────────────────┼───────────────────┼──────────────┤
│ 模拟网关  │ 普通电话/传真    │ FXS(接话机)/       │ 小规模、      │
│          │                │ FXO(接外线)        │ 接老设备      │
│ 数字网关  │ 运营商E1/T1中继  │ E1(30路)/T1(24路) │ 企业出局中继  │
│ 中继网关  │ SIP↔PSTN大容量  │ 千兆网+E1/光口     │ 运营商级接入  │
│ SBC      │ 跨网络边界会话   │ 双网卡(内/外)      │ 安全/互通/    │
│          │                │                   │ NAT穿透      │
└──────────┴────────────────┴───────────────────┴──────────────┘
```

> **注意**：SBC（会话边界控制器）虽常归为网关家族，但更偏"安全边界"：做拓扑隐藏、防攻击、NAT 穿透、媒体加密，是网关的"安全升级版"。

### 网关位置图

```
┌────────────────────┐         ┌──────────┐        ┌────────────────────┐
│  VoIP 世界 (IP网络) │         │          │        │ 传统电话网 (PSTN)   │
│ ┌────────────────┐ │         │   网关    │        │ ┌────────────────┐ │
│ │ IP-PBX 服务器  │ │         │ 协议转换   │        │ │ 运营商交换机    │ │
│ ├────────────────┤ │ ──────> │ 编解码转换 │ ─────> │ ├────────────────┤ │
│ │ SIP话机/软电话 │ │         │ SIP⇄PSTN  │        │ │ 手机/普通座机   │ │
│ └────────────────┘ │         │          │        │ └────────────────┘ │
│ 协议: SIP           │         └──────────┘        │ 信令: ISDN/SS7      │
│ 编码: G.711/G.729   │                             │ 承载: 电路时隙      │
│ 承载: IP 包         │                             │ 模拟/数字中继       │
└────────────────────┘                             └────────────────────┘
        网关居中做"语言翻译"，让两个世界能互相打电话
```

## 四、服务器：通信系统的"大脑"

**SIP 服务器 / IP-PBX = 大脑**：决定呼叫往哪走、谁能打给谁、要不要录音计费。

### 4.1 SIP 服务器四角色（RFC 3261 定义，实际常合一部署于 IP-PBX）

```
┌───────────────┬──────────────────────┬──────────────┐
│ 角色           │ 职责                  │ 一句话        │
├───────────────┼──────────────────────┼──────────────┤
│ 注册服务器     │ 记录"用户当前IP在哪"   │ 话机上线报个到 │
│ Registrar     │                      │              │
│ 代理服务器     │ 转发SIP请求、路由决策   │ 呼叫的"邮局分拣"│
│ Proxy         │                      │              │
│ 重定向服务器   │ 返回"该打这个地址"     │ 指路不亲自送   │
│ Redirect      │                      │              │
│ 位置服务器     │ 存绑定表(账号↔IP)     │ 通讯录+地址本  │
│ Location      │                      │              │
└───────────────┴──────────────────────┴──────────────┘
```

### 4.2 IP-PBX 核心能力（功能清单）
- **呼叫控制**：路由、转接、保持、前转、三方通话
- **媒体处理**：会议桥、IVR 语音导航、语音邮件、录音
- **互联互通**：经网关出局 PSTN、SIP 中继对接运营商
- **运维管理**：分机管理、计费（CDR）、号码黑白名单、QoS 标记
- **增值业务**：电话会议、排队（ACD）、话务报表

## 五、三者如何协作？两次真实通话

### 场景 A：两个 SIP 话机互打（纯 IP，不经过网关）
A 拨 B 分机 → A 终端发 SIP INVITE → **服务器**查位置表（B 当前 IP）→ 转给 B → 双方终端**直接建立 RTP 媒体流**。全程 IP 网内，**网关不参与**。

### 场景 B：SIP 话机打客户手机（必须经过网关）
拨 138xxxx → 终端发 INVITE → **服务器**判断是外线 → 路由到**网关** → SIP 翻译成 PSTN 信令，经运营商中继打到手机 → 接通后媒体流由网关在 IP 侧与 PSTN 侧之间转换桥接。

```
 终端A          ① SIP INVITE      IP-PBX
(SIP话机) ────────────────────> (服务器)
    ▲                                │ ② 路由外线
    │                                ▼
    │   RTP媒体(经网关处理)      ┌────────┐    ③ PSTN呼叫   客户手机
    └─ ── ── ── ── ── ── ── ─ │  网关   │ ─────────────>  (PSTN)
                              │SIP→PSTN│ <─ ── 语音流 ── ──
                              └────────┘
  协作链：终端 → 服务器(路由) → 网关(出PSTN) → 手机；信令与媒体分走两条路
```

> **关键认知**：同一局域网内，SIP 信令走服务器，RTP 媒体尽量"直连"。场景 A 媒体两端终端直连；场景 B 媒体必须过网关（一侧是 PSTN，无法直连 IP）。

## 六、排错实战：组件故障怎么定位

**四步定位口诀**：

```
① 看终端：话机灯亮否？是否注册成功（屏幕"已注册"）
          灯不亮→查网线/PoE；未注册→查账号密码
② 查服务器：IP-PBX 上看分机状态、CDR 日志，
            确认呼叫是否被路由/拒绝
③ 测网关：打外线不通→查中继状态（E1 告警灯、
          SIP 中继 UP/DOWN），抓包看 SIP 是否送到网关
④ 验互通：网关到运营商链路通不通（ping 中继地址），
          媒体地址协商是否正确
```

**记忆锚点**：**"终端管收听、服务器管路由、网关管出局"**——三句话在故障会上迅速分清责任边界：是话机没上线、服务器没路由、还是网关没出局。
