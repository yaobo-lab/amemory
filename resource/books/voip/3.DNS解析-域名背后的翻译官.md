# VoIP 学习笔记 · 第 3 篇：DNS 解析 —— 域名背后的"翻译官"

> 系列上下文：上一期讲 DHCP（话机如何拿到 IP），本篇讲拿到 IP 之后，话机如何通过 `sip.company.com` 这样的域名找到 SIP 服务器。

---

## 一、DNS 是什么：网络世界的"电话簿"

**核心定义**：DNS（Domain Name System，域名系统）= 把人类记得住的**域名**翻译成机器认得的 **IP 地址**。

**类比**：通讯录——你不用记客户手机号，搜"张总"就能拨号。话机填 `sip.company.com`，DNS 查出 `192.168.1.10`。

**有/无 DNS 对比**：

```
没有 DNS：
  访问百度    → 记 110.242.68.66
  访问SIP服务 → 记 192.168.1.10
  200台话机逐台手填IP（同"静态IP逐台配置"一样痛苦）

有 DNS：
  话机只配域名 sip.company.com，DNS 自动查 IP
  服务器IP变了 → DNS改一条记录，全网话机自动跟随
```

**DNS 两大核心作用**：
1. **正向解析**（域名 → IP）：最常用，话机查 SIP 服务器 IP 就靠它
2. **反向解析**（IP → 域名）：用于服务器身份验证，防伪造

---

## 二、DNS 解析流程：递归 + 迭代

查询 `sip.company.com` 背后的完整链路 = **递归查询（客户端→本地DNS）** + **迭代查询（本地DNS 逐级问）**。

```
用户PC/话机        本地DNS服务器        根DNS(.)      TLD(.com)     权威DNS(company.com)
    │                  │                 │              │                │
    │─1.递归查询请求──→│                 │              │                │
    │ "sip.company.com │─2.迭代查询─────→│              │                │
    │    的IP是多少？" │←3."去问.com的DNS"│              │                │
    │                  │─4.查询.com DNS────────────────→│                │
    │                  │←5."去问company.com的权威DNS"────│                │
    │                  │─6.查最终记录───────────────────────────────────→│
    │                  │←7.返回A记录 "sip.company.com = 192.168.1.10"────│
    │←8.返回最终结果───│                 │              │                │
```

**递归 vs 迭代**：

| 方式 | 口诀 | 说明 |
|---|---|---|
| 递归 | "你帮我跑完全程" | 话机只问本地DNS一次，本地DNS代劳跑完所有查询，带回最终结果 |
| 迭代 | "你告诉我下一步问谁" | 本地DNS逐级向根、TLD、权威提问，每级只告知"下一跳去哪"，最后在权威服务器拿到答案 |

**举例（话机查 `sip.company.com`）**：
1. 话机向本地DNS（如 `8.8.8.8`）递归查询
2. 本地DNS 向根DNS（`.`）迭代查询 → 根答"去问 .com 的DNS"
3. 本地DNS 向 .com TLD 查询 → TLD 答"去问 company.com 的权威DNS"
4. 本地DNS 向权威DNS 查询 → 答 `sip.company.com = 192.168.1.10`
5. 本地DNS 返回结果 → 话机向 `192.168.1.10:5060` 发起 SIP 注册

## 三、DNS 域名层级：一棵倒着长的树

域名体系 = **从右到左、从根到叶的层级树**，这解释了为什么解析要"逐级查询"。

```
                        ┌──────────┐
                        │  根域 .   │  全球13组根服务器
                        └────┬─────┘
            ┌────────────────┼────────────────┐
       ┌────┴────┐      ┌────┴────┐      ┌────┴────┐
       │ .com    │      │ .net    │      │ .cn     │
       │ TLD     │      │ TLD     │      │ ccTLD   │
       └────┬────┘      └─────────┘      └────┬────┘
      ┌─────┴──────┐                    ┌─────┴──────┐
  company.com  example.com          company.cn   netease.cn
   (二级域)                             (二级域)
      │
  ┌───┼────────┬──────────┐
 sip.  www.   voip.    config.
(三级子域)              (四级子域)
```

**`sip.company.com.` 从右到左拆解**：
- 最后的 `.` = 根域（通常省略不写，完整域名末尾都有它）
- `com` = 顶级域（TLD），表示类别（商业组织）
- `company` = 二级域，公司在注册商购买的那一段
- `sip` = 三级子域，管理员在自家DNS上自行创建，指向 SIP 服务器

**VOIP 常用域名设计**（统一在 `company.com` 权威DNS上管理）：

| 域名 | 用途 |
|---|---|
| `sip.company.com` | SIP 注册服务器 |
| `config.company.com` | 配置文件下载（HTTP/TFTP） |
| `provisioning.company.com` | 话机自动配置（OTA） |

## 四、DNS 记录类型：不只是"域名转IP"

| 类型 | 名称 | VOIP 中的用途 | 示例值 |
|---|---|---|---|
| **A** | IPv4地址记录 | 话机查 SIP 服务器 IP（最常用） | `192.168.1.10` |
| **AAAA** | IPv6地址记录 | IPv6 环境必备 | `2001:db8::10` |
| **SRV** | 服务定位记录 | 话机自动发现 SIP 服务器（**VOIP核心**） | 端口 `5060` |
| **NAPTR** | 命名权威指针 | 选择传输协议 TCP/UDP/TLS（高级服务发现） | `SIP+D2U` |
| **TXT** | 文本记录 | SPF/DKIM 验证，安全辅助 | `v=spf1 ...` |
| **CNAME** | 别名记录 | 域名指向另一域名，简化管理 | `sip2.company` |
| **PTR** | 反向解析记录 | SIP 服务器身份验证，防伪造/反查 | `sip.company.com` |

**VOIP 最关键的 3 种记录**：
- **A 记录**：最基础，`sip.company.com` → `192.168.1.10`，话机靠它拿服务器 IP
- **SRV 记录**：告诉话机"SIP 服务在哪个域名、哪个端口"，格式 `_sip._udp.company.com`
- **NAPTR 记录**：最高层调度，按灵活规则决定最终选哪种协议/服务，并指向具体 SRV 记录，构建从"服务需求"到"网络地址"的完整解析链

**一条 SRV 记录解读**：

```
_sip._udp.company.com  SRV  10   60   5060  sip1.company.com
 └─UDP协议的SIP服务         │    │     │         └─目标服务器
                          │    │     └─端口
                       优先级  权重
```
话机拿到 SRV 后 → 再查 `sip1.company.com` 的 A 记录拿 IP → 向 `IP:5060` 注册。

## 五、DNS 在 VOIP 中的应用：话机自动发现 SIP 服务器

不用 DHCP Option 120 时，话机可通过 **DNS 自动发现** SIP 服务器。三步链路：**NAPTR 选协议 → SRV 选服务器 → A 记录选 IP**，话机端只需配一个域名 `company.com`。

```
IP话机(仅配域名          DNS服务器                    SIP服务器
 company.com)               │                      sip.company.com:5060/UDP
    │─1.查NAPTR──────────→│
    │  "company.com的NAPTR记录?"
    │   ┌─────────────────────────────────────────────┐
    │   │ 返回: order=100 pref=10 flags=U             │
    │   │       service=SIP+D2U                       │
    │   │  D2U=UDP | D2T=TCP | D2S=TLS加密            │
    │   └─────────────────────────────────────────────┘
    │←2.选定UDP──────────│
    │─3.查SRV───────────→│ "_sip._udp.company.com 的SRV记录?"
    │   ┌─────────────────────────────────────────────┐
    │   │ 返回: priority=10 weight=60 port=5060       │
    │   │              target=sip1.company.com        │
    │   │       priority=20 weight=40 port=5060       │
    │   │              target=sip2.company.com        │
    │   └─────────────────────────────────────────────┘
    │←4.拿到地址─────────│
    │─5.向 sip1.company.com:5060 发起注册──────────────────────────→│
```

**完整流程**：
1. 查 `company.com` 的 NAPTR → 得知用 UDP 传输（D2U）
2. 查 `_sip._udp.company.com` 的 SRV → 得知优先选 `sip1.company.com:5060`
3. 查 `sip1.company.com` 的 A 记录 → 得知 IP `192.168.1.10`
4. 向 `192.168.1.10:5060/UDP` 发起 SIP 注册
5. **sip1 故障 → 自动切到 SRV 优先级次之的 sip2 → 内置高可用**

**SRV 优先级与权重**：多条 SRV 时，先按 **priority** 排序（数字越小越优先），同一优先级内按 **weight** 加权选择（类似负载均衡）——天然实现 SIP 服务器多机高可用。

## 六、DNS 缓存与 TTL

若每次都从根一路查到权威，速度慢。实际 DNS 有**缓存机制**：查过的结果被各级缓存，TTL（Time To Live）写在记录里，决定"这条记录能存多久"，到期后需重新完整解析。

| 缓存层 | 缓存位置 | 说明 |
|---|---|---|
| 话机本地缓存 | 话机内存 | 最短缓存（秒级~分钟级） |
| 本地DNS缓存 | 路由器/运营商DNS | 按 TTL 缓存，话机多数从这里拿结果 |
| TLD缓存 | 顶级域DNS | 缓存权威DNS地址，避免反复查根 |

**VOIP 场景 TTL 建议**：
- TTL 太长 → 服务器 IP 变更后话机长时间连旧 IP
- TTL 太短 → 查询频繁增加延迟
- **建议 300~600 秒（5~10 分钟）**——既不过度查询，IP 变更也能较快生效

## 七、DNS 排错：话机注册失败怎么查

```
                ┌──────────────────────────┐
                │ 现象：话机注册SIP服务器失败 │
                └────────────┬─────────────┘
                             ▼
                ┌──────────────────────────┐
                │ 话机能ping通DNS服务器?     │  ping 8.8.8.8 / 内网DNS
                └──┬───────────────────┬───┘
                 否│                   │是
                   ▼                   ▼
        ┌──────────────────┐  ┌────────────────────────┐
        │ 检查网络层        │  │ 能nslookup解析域名?     │
        │ 网关/路由/DHCP    │  │ nslookup sip.company.com│
        │ 是否拿到IP和DNS   │  └───────────┬────────────┘
        └──────────────────┘              ▼
                              ┌────────────────────────┐
                              │ DNS能解析出IP吗?        │
                              └──┬─────────────────┬──┘
                               否│                 │是
                                 ▼                 ▼
                      ┌──────────────────┐  ┌──────────────────┐
                      │ DNS记录缺失/错误  │  │ 话机能ping通该IP? │
                      │ 检查A记录/子域记录│  └───────┬──────────┘
                      └──────────────────┘          ▼
                                        ┌──────────────────────┐
                                        │ 5060端口可达?         │
                                        │ telnet IP 5060        │
                                        └──┬─────────────────┬──┘
                                         否│                 │是
                                           ▼                 ▼
                                ┌──────────────────┐  ┌──────────────────┐
                                │ 防火墙/端口问题   │  │ DNS正常           │
                                │ 检查5060放行/NAT  │  │ 查SIP账号密码/    │
                                └──────────────────┘  │ 服务器配置        │
                                                       └──────────────────┘
```

**三个最常用排错命令**：

| 命令 | 示例 | 用途 |
|---|---|---|
| nslookup | `nslookup sip.company.com` | 查域名是否解析出 IP |
| dig | `dig SRV _sip._udp.company.com` | 查 SRV 记录是否配置正确 |
| ping | `ping sip.company.com` | 快速验证解析 + 网络可达性 |
