# DHCP Option 大揭秘：那些隐藏的配置参数 —— 学习笔记

（原创 @乘风VoIP实战派）

## 〇、开篇引子：一个让人迷惑的现象

公司新到一批 IP 话机，IT **没给任何一台手动配置**（没填 SIP 服务器、没填账号、没填 TFTP 地址），结果话机一插网线上电，就**自动下载配置文件 → 自动找到 SIP 服务器 → 自动完成注册**，拿起来就能打电话。

> 核心问题：话机没连过服务器，怎么知道去哪下载配置、SIP 服务器是谁？
> 答案：藏在 DHCP 的 **Option** 里。DHCP 不只是分配 IP，还能"顺手"塞一大堆隐藏配置参数给客户端。

---

## 一、什么是 DHCP Option？—— 协议里的"附加信息槽"

### 1.1 从"分 IP"到"送配置"
- DHCP 四大报文（Discover / Offer / Request / ACK）里，除了 IP、掩码、网关，还有一个灵活的**扩展区域 = Option（选项）**。
- 每个 Option 像"带标签的包裹"，采用 **TLV 结构**：

```
+----------+----------+------------------------+
| Code(1B) | Len(1B)  |      Value(Len B)      |
+----------+----------+------------------------+
   │           │              │
 Option编号   值的长度      具体参数内容
 (如66=TFTP)               客户端/服务器都靠 Code 识别"这是什么配置"
```

### 1.2 谁决定要哪些 Option？—— Option 55
- **Option 55（Parameter Request List，参数请求列表）** 是关键。
- 话机在 Discover 里用 Option 55 声明需求（3 网关、6 DNS、42 NTP、66 TFTP、120 SIP……），服务器在 ACK 里**只回话机请求的那些 Option**——高效、不浪费。

```
            "请求—回应"机制
┌──────────────┐   Discover: Option55(请求列表)   ┌──────────────┐
│   IP 话机     │ ───────────────────────────────► │ DHCP 服务器   │
│              │              + Option 60(厂商标识) │              │
│              │ ◄─────────────────────────────── │              │
└──────────────┘   ACK: IP + Option 3/6/42/66/67/120… └─────────────┘

服务器 ACK 实际下发示例:
  Option 3   = 10.10.10.1        (网关)
  Option 6   = 10.10.30.53       (DNS)
  Option 42  = 10.10.30.100      (NTP)
  Option 66  = 10.10.30.50       (TFTP)
  Option 67  = SIP0004f2xxxx.cfg (配置文件名)
  Option 120 = 10.10.10.10       (SIP服务器)
→ 话机"照单全收"，零手动配置
```

## 二、话机零配置启动：6 步自动就绪

串起第 05 篇（VLAN）与第 07 篇（802.1X）的"自动上岗"全流程：

```
① 取IP    VLAN/802.1X 通过后，广播 DHCP Discover(带 Option55+60)
           → 拿到 IP、网关、DNS
           【前提：第05篇 VLAN 划分 + 第07篇 802.1X 认证已通过，端口已授权】
              ▼
② 收Option 服务器 ACK 内携带 Option 42/66/67/120 等 → 话机"读清单"
           （这些 Option 是后续自动配置的依据）
              ▼
③ 下配置  按 Option 66(TFTP地址) + Option 67(文件名) 下载配置文件 .cfg/.xml
           （配置含 SIP 账号、服务器、编解码、按键等）
              ▼
④ 找SIP   按 Option 120 找到 SIP 服务器域名/IP
           （无需手动填，话机自动定位注册服务器）
              ▼
⑤ 对时间  按 Option 42 向 NTP 服务器同步时间
           （证书/计费都依赖准确时间；时间不准 → TLS 证书校验失败、计费异常）
              ▼
⑥ 注册通话 话机用配置向 SIP 服务器注册 → 摘机即可通话，全程零手动配置 ✅
```

## 三、VoIP 常用 Option 速查表

Option 编号范围 0~254，VoIP 场景主力如下：

| Option | 名称 | 作用（话机用它做什么） | 典型取值 |
|---|---|---|---|
| 3 | Router 默认网关 | 话机出网的第一跳 | 10.10.10.1 |
| 6 | DNS Server | 解析 SIP 服务器域名 | 10.10.30.53 |
| 15 | Domain Name | 所属域名（用于 SIP URI） | office.example.com |
| 42 | NTP Server | 时间同步（证书/计费依赖） | 10.10.30.100 |
| 66 | TFTP Server Name | 配置文件服务器地址 | 10.10.30.50 |
| 67 | Bootfile Name | 配置文件名 | SIP0004f2xxxx.cfg |
| 120 | SIP Server | 自动发现 SIP 注册服务器 | 10.10.10.10 / sip.example.com |
| 132 | Voice VLAN | 语音 VLAN ID（第05篇讲过） | 10 |
| 150 | TFTP（Cisco） | Cisco 设备的 TFTP 地址 | 10.10.30.50 |
| 43 | Vendor Specific | 厂商私有参数（华为/Aruba等） | 十六进制子选项 |
| 60 | Vendor Class | 话机自报"我是谁"（区分设备类型） | String：话机型号 |

**记忆技巧：按用途分四组**

```
┌─────────────┬─────────────┬───────────────┬─────────────┐
│  网络基础组   │   时间组     │   配置下发组    │  语音业务组   │
├─────────────┼─────────────┼───────────────┼─────────────┤
│ 3  网关      │ 42 NTP      │ 66 TFTP地址    │ 120 SIP服务器 │
│ 6  DNS      │  (证书校验、  │ 67 配置文件名   │ 132 语音VLAN  │
│ 15 域名      │   计费准确)  │ 150 Cisco TFTP│             │
│             │             │ 43 厂商私有    │             │
│ 让话机连上网  │ 依赖准确时间  │               │ 自动找服务器   │
└─────────────┴─────────────┴───────────────┴─────────────┘
记住四组 → 排错时"按组检查"
```

## 四、重点 Option 详解（上）：配置文件自动下发

### 4.1 Option 66 + 67：话机的"自助取餐口"

比喻：话机是新员工——
- **Option 66** 告诉它"食堂在 3 楼"（TFTP 服务器地址）
- **Option 67** 告诉它"你的餐盒编号是 SIP0004f2xxxx.cfg"

话机自己跑去取回包含 SIP 账号、服务器地址、拨号规则等的完整配置文件。

```
┌──────────┐  ①请求文件  ┌──────────────┐  ②返回文件  ┌───────────────┐
│  IP话机   │ ──────────► │ TFTP 服务器   │ ──────────► │ 配置文件        │
│ 已拿到IP  │             │ 10.10.30.50  │             │ SIP0004f2xxxx │
│ 读66/67   │             │ 存 cfg 文件   │             │    .cfg        │
└──────────┘             └──────────────┘             └───────────────┘

配置文件 cfg/.xml 内含:
SIP 账号/密码、注册服务器、代理、编解码优先级、拨号规则、按键映射、显示语言…
→ 话机解析后"变身"为按企业规范工作的话机，无需人工逐台配置
```

💡 **为什么不用 Option 66 直接给 SIP 服务器？**
66/67 解决的是"**批量下发复杂配置**"，比逐台手填高效百倍——改一处服务器地址，全公司话机下次启动自动更新。

⚠️ **注意：Option 66 与 Option 150 的关系**
- Cisco 设备传统用 **Option 150** 指定 TFTP（可配多个做冗余）；标准做法是 **Option 66**。
- 现代话机两者大多都认 → **建议两个都配**，兼容性最好。
- 华为/H3C 主要用 66+67（或 Option 43 下发厂商参数）。

## 五、重点 Option 详解（下）：SIP 发现与时间同步

### 5.1 Option 120：话机的"SIP 服务器导航"
- 有了配置还不够，话机还要知道"去哪注册"。
- **Option 120（RFC 3361）** 专门携带 SIP 服务器信息：域名（需配 Option 6 的 DNS 解析）或 IP 列表。
- 话机读完 120，直接向该服务器发起 REGISTER。

### 5.2 Option 42：别小看"对时"
话机时间不准引发两大问题：
1. **TLS 证书"有效期"校验失败**（证书还没生效或已过期）
2. **通话计费、录音时间戳错乱**

Option 42 指向 NTP 服务器，话机启动即校准，是稳定运行的隐形前提。

```
                    "注册三件套"协同
┌──────────┐   REGISTER    ┌───────────────┐
│  IP话机   │ ─────────────►│  SIP 服务器    │
│ 已下配置  │               │ 10.10.10.10   │
│          │               │ (Option 120)  │
│          │ 时间同步请求    └───────────────┘
│          │ ┈┈┈┈┈┈┈┈┈┈┈┈┈► ┌───────────────┐
└──────────┘               │  NTP 服务器    │
                           │ 10.10.30.100  │
                           │ (Option 42)   │
                           └───────────────┘

三者缺一不可的"隐性依赖"：
• Option 120 缺失/错误 → 不知 SIP 服务器在哪 → 无法注册(摘机忙音/未注册)
• Option 42  缺失/错误 → 时间偏差大 → TLS 证书校验失败 → 注册被拒
• Option 6 (DNS) 也须正确：120 常给域名 sip.example.com，需 DNS 解析
→ 120 + 42 + 6 = "注册三件套"，任一出问题都注册不上
```

## 六、实战：DHCP 服务器 Option 配置示例

**Cisco IOS DHCP 配置**
```
ip dhcp pool VOICE
   network 10.10.10.0 255.255.255.0
   default-router 10.10.10.1          ! Option 3
   dns-server 10.10.30.53             ! Option 6
   option 42 ip 10.10.30.100          ! NTP
   option 66 ip 10.10.30.50           ! TFTP地址
   option 67 ascii SIP0004f2xxxx.cfg  ! 配置文件名
   option 120 ip 10.10.10.10          ! SIP服务器
   option 150 ip 10.10.30.50          ! Cisco TFTP(冗余)
```

**华为 / H3C DHCP 配置**
```
dhcp server ip-pool voice
   gateway-list 10.10.10.1
   network 10.10.10.0 mask 255.255.255.0
   dns-list 10.10.30.53
   option 42 ip-address 10.10.30.100
   option 66 ip-address 10.10.30.50
   option 67 ascii SIP0004f2xxxx.cfg
   option 120 ip-address 10.10.10.10
   option 43 hex 010A...              ! 厂商私有(可选)
```

> **要点**：不同厂商命令语法不同（`option 66 ip` vs `option 66 ip-address`），但 **Option 编号与含义全球统一**——这正是"标准 Option"的价值：**换设备不用改话机逻辑**。

**厂商差异对比**

```
┌───────────────┐ ┌───────────────┐ ┌─────────────────┐
│ 标准/华为/H3C  │ │  Cisco 传统    │ │  通用最佳实践     │
├───────────────┤ ├───────────────┤ ├─────────────────┤
│ 66 = TFTP地址  │ │ 150 = TFTP地址 │ │ 66+67 必配       │
│ 67 = 文件名    │ │ (也可配66/67)  │ │ 150 视厂商补配    │
│ 43 = 厂商私有  │ │ 多TFTP冗余好   │ │ 120/42/3/6 全配  │
│ 最通用、跨厂商  │ │ Cisco/老设备   │ │ 覆盖绝大多数场景  │
│ 兼容好 ✅推荐  │ │ 惯用150 ⚠️    │ │ 避免换品牌即失效  │
└───────────────┘ └───────────────┘ └─────────────────┘
核心原则：Option 编号含义全球统一，差异只在"厂商惯用哪一支配 TFTP"
```

## 七、排错实战：话机"配置下不来"

**现象**：话机拿到 IP，但一直停在"正在下载配置"或注册失败。

**排查四步**：

```
① 看 Option 66/67 ──► 服务器地址填对了吗？文件名拼对了吗？
                       (可在话机 Web 管理页看"已获取 Option"列表)
② 看 TFTP 可达   ──► 从话机网段 ping 10.10.30.50；
                       TFTP 端口 69 是否被防火墙拦截？文件权限可读？
③ 看 Option 120/42/6 ► SIP 服务器地址对吗？DNS 能解析 sip.example.com 吗？
                       NTP 通吗？——任一缺失都会注册失败
④ 抓包定位       ──► 在话机端口抓 DHCP 报文，确认 ACK 里确实带了期望的 Option
                       (常犯错误：Option 配在了错误的地址池/VLAN)
```

**一句话口诀**：
> 先查"66/67 对不对"，再查"TFTP 通不通"，三查"120/42/6 齐不齐"，四查"地址池配没配错 VLAN"。

---

## 📌 本篇核心一句话

DHCP Option 是话机零配置的幕后功臣：**Option 55 点菜、66+67 取配置、120 找 SIP、42 对时间、6 做解析**——配好这一套，话机插线即用；排错按"四组"逐项核对即可。
