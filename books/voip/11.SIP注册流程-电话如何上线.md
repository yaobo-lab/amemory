# SIP注册流程：电话如何"上线"

> 本篇核心：**话机如何用 REGISTER 把自己"登记"到服务器，并在过程中安全完成身份认证。** 这是所有 VoIP 通话的前提——不"上线"，就接不到、也打不出电话。

---

## 一、什么是注册？先搞懂"服务器凭什么找到你"

### 1.1 生活类比：分机登记本

- SIP 服务器 = 公司**前台**，话机 = **工位**，前台手里有一本"分机登记本"：`分机号 ↔ 现在坐在哪个工位`
- 话机开机第一件事：告诉前台"我是 phone01，我此刻坐在 192.168.1.100"——这个动作就是**注册**
- 这本登记本在 SIP 世界里叫 **Location Service（位置服务）**

**技术定义**：SIP Registrar（注册服务器）维护一张绑定表，把 **AOR**（Address of Record，地址记录，如 `sip:phone01@company.com`）映射到一组 **Contact**（话机此刻可达的 URI，如 `sip:phone01@192.168.1.100:5060`）。**注册 = 动态地"写这张表"**。

```
+------------------------------------------------+
|           Registrar 绑定表 (Location Service)   |
|------------------------------------------------|
|  AOR (我是谁)              Contact (我现在在哪) |
|  sip:phone01@company.com → sip:phone01@        |
|                            192.168.1.100:5060  |
+------------------------------------------------+
```

### 1.2 为什么非注册不可？

话机的地址是**动态且私有的**：
- **IP 会变**：DHCP 重新分配、重启后地址可能不同
- **在 NAT/防火墙后**：服务器看到的是公网地址，话机只知道私网地址
- **服务器要把 INVITE 投送到"此刻"的地址**：只有注册表实时更新，来电才能送达

一句话：**注册 = 把"我是谁"和"我现在在哪"实时告诉服务器。**

```
   ✗ 未注册：找不到话机            ✓ 已注册：绑定写入 Location
+------------------+             +------------------+
|  IP话机           |             |  IP话机           |
| 192.168.1.100    |             | 192.168.1.100    |
|      ✗ (断)      |             |      | REGISTER  |
|  SIP服务器        |             |      v           |
|  Location: 空     |             |  SIP服务器        |
| 来电INVITE无处送达 |             |  绑定OK→来电送达  |
+------------------+             +------------------+
```

## 二、注册涉及谁？用什么消息？

### 2.1 三个角色

| 角色 | 职责 |
|---|---|
| **话机（UA / User Agent）** | 发起注册、提供身份凭证 |
| **SIP 代理/认证者（Proxy + Authenticator）** | 接收 REGISTER，触发身份认证 |
| **Registrar + Location Service** | 真正落库 AOR ↔ Contact 绑定 |

实际部署中三者常合为一体（如 IP-PBX）。

```
 IP话机          SIP代理/认证者              Registrar
 (UA/申请者)     (Proxy+Authenticator)      (Location Service)
    |  ① REGISTER   |  ② 校验+写入绑定        |
    |------------->|----------------------->|
    |               |   触发Digest挑战        | 保存 AOR→Contact
                                                 绑定表
  后续来电：Proxy 查 Location Service 找到 Contact，再转发给话机
```

### 2.2 REGISTER 的关键头域

| 头域 | 作用 |
|---|---|
| **To / From** | 通常都是同一个 AOR（我要注册的身份） |
| **Contact** | **注册核心**：话机"此刻可达"的 URI（如 `sip:phone01@192.168.1.100:5060`） |
| **Call-ID** | 本次注册会话的唯一标识 |
| **CSeq** | 递增序号；重传、重注册时 +1 |
| **Via** | 请求经过的路径，响应沿原路返回 |
| **Expires** | 注册有效期（秒），到期需重注册 |
| **Authorization / Proxy-Authorization** | 摘要认证凭证（首次通常为空，被挑战后补上） |

## 三、注册完整流程：四步上线

出于安全，SIP 注册几乎总是走**挑战-响应（Digest 认证）**：第一次先"亮明身份但不交密码"，被服务器拒绝后，再用密码算出一个**一次性的响应值**来证明"我确实知道密码"。

```
 IP话机                                SIP服务器
   | ① REGISTER(首次,无Authorization)        |
   |   To/From=AOR, Contact=当前地址,        |
   |   Expires=3600                         |
   |-------------------------------------->|
   |                                       |
   |   ② 401 Unauthorized(挑战)             |
   |   WWW-Authenticate: Digest realm,nonce|
   |<--------------------------------------|
   |                                       |
   | ③ REGISTER(带Authorization, CSeq+1)    |
   |   Authorization: Digest response=MD5()|
   |-------------------------------------->|
   |                                       |
   |   ④ 200 OK(授权成功)                   |
   |   Contact+Expires→绑定写入Location     |
   |<--------------------------------------|
```

**逐条拆解**：
1. 话机发出第一条 REGISTER：`To: sip:phone01@company.com`，`Contact: sip:phone01@192.168.1.100:5060`，`Expires: 3600`，但**没有 Authorization**。服务器一看"谁知道你是不是真的 phone01"，直接回绝
2. 服务器回 `401 Unauthorized`，并在 `WWW-Authenticate` 里塞一个 **nonce**（本次会话一次性随机数）和 **realm**（域名）
3. 话机用密码和 nonce 算出 response，重发 REGISTER（CSeq +1）并带上 `Authorization`
4. 服务器用同样的密码和 nonce 自己算一遍，对上了就回 `200 OK`，并把"phone01 → 192.168.1.100:5060，有效期 3600 秒"的绑定写进 Location Service

> **要点**：服务器用 nonce 发起挑战；话机用密码算出 response 证明"我知道密码"，但**密码本身从不经过网络**——即使被抓包，攻击者拿到的 response 也无法反推密码或重放。

## 四、Digest 摘要认证：密码为何不必明文传输

如果直接明文发密码，局域网一抓包就泄露。SIP 用 **HTTP Digest 式挑战-响应**：双方都"知道密码"，但网络上只交换**由密码参与算出的哈希值**。

```
 SIP服务器  --①下发nonce-->  IP话机
 (生成nonce) <--②回response-- (持有密码)

   A1 = username : realm : password
   A2 = method : uri
                \           /
                 \         /
   response = MD5( MD5(A1) : nonce : MD5(A2) )
   服务器用同一密码和nonce复算，一致即通过
```

**算给你看**：假设账号 `phone01@company.com`，密码 `voippass`，服务器下发 `nonce = a1b2c3d4`，注册目标 `sip:company.com`：

```
A1 = phone01 : company.com : voippass
A2 = REGISTER : sip:company.com
response = MD5( MD5(A1) : "a1b2c3d4" : MD5(A2) )
```

话机把这串十六进制 response 放进 `Authorization` 头发出去；服务器手握同样的密码独立算一遍——**两边结果一致，就证明话机确实知道密码，但密码明文从没上过网络**。

> 注：若服务器启用 `qop=auth`，公式会加上 `nc`（防重放计数）、`cnonce` 等参数，原理相同，安全性更强。

## 五、注册不是一次性的：重注册与注销

绑定有"保质期"。`Expires` 告诉服务器这条绑定活多久（常见 3600 秒）。到点不续，服务器就删除——话机"失联"，来电找不到。

```
 t=0            t=1800          t=3600          t=5400
 ●───────────────○───────────────○───────────────○────→
 注册成功         提前一半重注册    再次重注册       周期重注册...
 Expires=3600    刷新有效期       绑定持续有效

 注销：发送 REGISTER 并将 Expires 设为 0，服务器立即删除该绑定
```

**工程实践**：
- 话机一般在 **Expires 过半**（如 3600 秒则第 1800 秒）就主动重注册，确保绑定"无缝续期"
- 位于 NAT 后的话机还需周期性**保活包 / STUN 保活**，否则即便注册成功，媒体端口也可能被 NAT 回收

## 六、排错实战：注册失败的常见"症状"

先看服务器**返回的状态码**，几乎能直接定位问题类别：

| 现象 / 返回码 | 可能原因 | 处理方向 |
|---|---|---|
| 反复 **401 / 407** | 密码错、账号被禁用 | 核对密码、账号状态、realm 是否一致 |
| **403** Forbidden | 域名/realm 错、未授权、黑名单 | 核对 SIP 域名、账号权限 |
| **408** Timeout | 服务器地址/端口错、网络不通、防火墙挡 5060 | 检查服务器地址、端口、路由、UDP 放行 |
| 注册 OK 但打不出 | 代理未授权 / 路由（Dialplan）错 | 检查代理地址、出局规则 |
| 注册 OK 但收不到来电 | Contact 是私网地址（NAT 穿透失败） | 见下方 NAT 排错拓扑 |

**最隐蔽的坑：注册成功却收不到来电**

话机在 NAT 后面，注册时 Contact 填的是**私网地址** 192.168.1.100。服务器"成功"记下了，但来电 INVITE 被发往这个公网不可达的私网地址，**直接被丢弃**——表现就是"能注册、能打出、但别人打不进来"。

```
 IP话机           NAT            SIP服务器(公网203.0.113.50)
192.168.1.100:5060  地址转换        |
    |--REGISTER-->|--Contact=私网地址-->|
    |             |               |  Location:
    |             |               |  phone01→192.168.1.100(私网!)
    |             |               |
    |< - - - - - 来电INVITE发往私网地址 - - -
    ✗ 被NAT丢弃：收不到来电

 修复：STUN保活 / SIP ALG / Outbound / 注册时填公网映射地址
```

## 本篇要点速览

```
注册本质   : AOR ↔ Contact 动态绑定，写入 Location Service
核心头域   : Contact(可达地址)、Expires(有效期)、Authorization(凭证)
四步流程   : REGISTER → 401挑战(nonce) → 带凭证REGISTER → 200 OK落库
Digest安全 : response=MD5(MD5(A1):nonce:MD5(A2))，密码从不出网
生命周期   : Expires过半重注册，Expires=0即注销；NAT后还需保活
排错口诀   : 401/407查密码，403查域名权限，408查网络端口，
             能注册打不进→八成是NAT私网Contact问题
```
