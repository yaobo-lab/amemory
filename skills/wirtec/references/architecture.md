# 分层架构

## 编译期依赖

一方产品代码只允许沿下列方向依赖：

```text
app ──> business ──> hal ──> drivers
 │          │          │          │
 └──────────┴──────────┴──────────┴──> pkg
```

依赖包括 `#include`、公开类型、符号调用、回调签名、宏引用和 CMake 链接，不能只看运行时调用方向或文件目录。

| 层             | 职责                                               | 允许依赖                                 | 禁止依赖                                         |
| -------------- | -------------------------------------------------- | ---------------------------------------- | ------------------------------------------------ |
| `app`          | 页面、组件、导航、LVGL 对象、UI 状态和 UI 线程调度 | `business`、`pkg`、`resource`、LVGL      | `hal`、`drivers`                                 |
| `business`     | 用例、业务校验、领域状态、业务事件                 | `hal`、`pkg`                             | `app`、`drivers`、`resource`、LVGL               |
| `business/dal` | 数据持久化、序列化、查询结果转换                   | business 内部模块、`hal`、`pkg`          | `app`、`drivers`、`resource`、LVGL               |
| `hal`          | 平台无关的硬件能力接口和类型转换                   | `drivers`、`pkg`                         | `app`、`business`、`resource`、LVGL              |
| `drivers`      | Linux、芯片、开发板、厂商 SDK 的具体操作           | 当前驱动单元、`pkg`、平台 SDK            | `app`、`business`、`hal`、其他独立驱动单元、LVGL |
| `pkg`          | 真正通用的基础组件                                 | 当前包、标准库、第三方库、通用底层包     | 产品业务层、硬件层、LVGL                         |
| `resource`     | 静态图片、字体等编译期资源                         | 资源生成工具；格式需要时可使用 LVGL 声明 | 应用行为和业务逻辑                               |

`src/business/dal` 是 business 的内部模块，不是独立架构层。`src/include` 也不是独立层；定义应回到其所有者目录。

## 归属判断

新增逻辑时依次判断：

1. 替换 LVGL 后仍成立的模型和规则，不应绑定在 UI 控件实现中，通常属于 `business`。
2. 更换开发板或桌面平台后仍成立的硬件能力接口属于 `hal`；具体平台调用属于 `drivers`。
3. 调用方若是 `app`，硬件请求仍须先由 `business` 提供面向用例的中立接口。
4. 领域决策属于 `business`，持久化操作属于 `business/dal`。
5. 下层需要触发上层动作时，发布由下层拥有的事件/回调或返回数据，不包含上层头文件。
6. 一个驱动需要协调另一个驱动时，将编排提升到 `hal`，不要建立驱动单元间依赖。

## 类型与接口所有权

- API 由哪一层提供，其请求、结果、错误、状态、事件和回调类型就由哪一层定义。
- 跨层结构体使用定宽整数、`bool`、枚举、字节缓冲区和语义明确的值对象。
- `business` 拥有领域模型，`app` 负责映射为 UI 状态。
- `hal` 公开平台无关的能力，不把驱动结果类型或 SDK 句柄直接交给 `business`。
- `drivers` 公共头只暴露中立 C 类型；平台实现文件可以包含 Linux、PulseAudio、FFmpeg 或厂商 SDK 头。
- 禁止通过 `business`、`hal`、`drivers` 或 `pkg` 公开 `lv_obj_t*`、`lv_event_t*` 等 LVGL 类型。

## LVGL 与 UI 线程

- 一方应用逻辑中只有 `app` 可以包含 LVGL、操作 LVGL 对象或公开 LVGL 类型。
- `business`、`hal`、`drivers`、`pkg` 必须保持 LVGL 无关。
- `resource` 只允许静态图片、字体等资源描述符，不得包含页面行为、业务判断或主动调用业务接口。
- 所有 LVGL 操作只能在 `app` 的 UI 线程发生。

## business 到 app 的通知

业务状态更新 UI 时使用 `src/business/notify` 的同步通知边界：

```text
business 发布事件
        ↓
app 注册的同步处理器
        ↓
ui_app_notify_post()
        ↓
UI 线程消费并操作 LVGL
```

必须遵守：

1. 事件、载荷和回调类型由 `business` 定义，不包含 UI 类型或 `app` 头文件。
2. 当前每类通知保存一个处理器，后注册覆盖先注册，传入 `NULL` 表示注销；若现有具体接口另有契约，以接口文档为准。
3. 发布函数在调用内同步执行处理器；事件顺序即发布顺序，借用载荷至少在回调返回前有效。
4. 回调运行在发布者线程。非 UI 线程中的 app 处理器只复制必要数据并投递 UI 任务。
5. app 初始化时注册，并在关闭时注销或提供等价的生命周期保护。
6. 处理器不得保存借用指针；延迟处理时由接收方复制数据，并在任务完成或投递失败时释放。
7. 调用外部处理器时不得持有 business 内部互斥锁；先复制处理器或状态快照，解锁后通知。

## 构建依赖

分层目标只公开必要头目录，并按同一方向链接：

```text
app_media_lvgl
    -> business_media
        -> hal_media
            -> driver_media_<platform>
```

历史主目标可能仍聚合源码或直接链接部分驱动/平台库。这是待迁移关系，不表示新增源码可以绕过分层。除非用户要求架构迁移，不扩大范围修复历史链接问题，但应明确报告。
